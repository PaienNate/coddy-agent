# 与 OpenAI 兼容的 HTTP API

只有在使用 **`go build -tags=http`**（`make build TAGS=http`）构建二进制文件时，才会发布 HTTP 界面。它公开 OpenAI 形态的路由以及 **`/coddy/*`** 辅助路由，背后由与 **`coddy acp`** 相同的会话管理器和 ReAct 智能体支撑。

它本身不是一个命令。只要 **`httpserver.enable`** 为真（除非文件另有说明，否则为真），**`coddy serve`** 就会运行它，并与配置启用的其他所有子系统（Telegram 网关、集群中继、cron 调度器）一起运行。它们共享一个会话管理器，因此机器人启动的对话就是此 API 列出、流式传输并可以继续的会话。

仅当你同时设置 **`ui`** 标签（例如 **`make build TAGS="http ui"`** 或 **`go build -tags=http,ui`**）时，才会包含内置的 SPA。仅使用 **http** 时，**`GET /`** 返回 **404** 并附带纯文本提示。

对于 **`Accept-Encoding`** 允许 gzip 的客户端，JSON 应答会带上 **`Content-Encoding: gzip`** 和 **`Vary: Accept-Encoding`**；事件流、文件和错误页面按原样发送。

## OpenAPI 与 Swagger UI

规范在每次请求时重新生成，以便与处理程序保持一致。

- **`GET /openapi.yaml`** - OpenAPI 3.0（YAML）；**`GET /openapi.json`** 以 JSON 镜像它（两者均为 **`Content-Disposition: inline`**）。
- **`GET /docs/`** - Swagger UI（静态资源打包在二进制文件中，不使用 CDN）。**`GET /docs`** 重定向到 **`/docs/`**。

## 身份验证（可选）

身份验证**默认关闭**（历史行为）。有两种凭据，任意一种都能打开同一道门：

- 供 API 客户端使用（`coddy --remote`、`coddy acp --remote`、集群中继、脚本）的**持有者令牌**；
- 供浏览器使用的**密码登录表单**，将在下方 [Web UI 登录](#web-ui-登录可选) 中描述。

设置持有者令牌，以便在将 API 暴露到回环地址之外时保护它：

- `config.yaml` 中的 `httpserver.auth_token`（支持 `${ENV}`），或
- `coddy serve` 上的 `--auth-token <token>`，或
- `CODDY_HTTP_TOKEN` 环境变量。

配置令牌后，每个 `/v1/*` 和 `/coddy/*` 路由都要求
`Authorization: Bearer <token>`，否则返回带 `WWW-Authenticate: Bearer` 质询的 `401`。SPA 外壳和静态资源保持公开，以便客户端可以加载并提示输入令牌；除非 `httpserver.public_docs: true`，否则 `/docs` 和 `/openapi.*` 受保护。令牌绝不会由 `GET /coddy/config` 返回（已脱敏；DTO 仅报告 `auth_configured`）。通过 `--auth-token` / `CODDY_HTTP_TOKEN` 传入的令牌绝不会写入 `config.yaml`，并且能在 `PUT /coddy/config` 热重载后保留。在网络上使用身份验证时，优先使用 TLS（或终止 TLS 的代理）。在没有令牌的情况下绑定非回环地址会记录启动警告，除非 `httpserver.allow_insecure: true`。

没有令牌时，界面未经过身份验证；请在适当的网络控制后运行。

在未配置任何凭据时，服务器仍会限制另一站点上的浏览器可以访问的内容，在默认的 `coddy serve` 上和 Docker 发布的端口上都是如此。它会拒绝：

- 一个到达回环地址且其 `Host` 不是回环名称（`localhost`、`*.localhost`、`127.0.0.0/8`、`::1`）的请求：`421`；
- 在任何地址上，一个改变状态的请求（除 `GET`、`HEAD` 和 `OPTIONS` 之外的任何方法）且携带一个既不是服务器自身、也非 `httpserver.cors` 所允许的 `Origin`：`403`。

不是浏览器的程序不发送 `Origin` 并拨打回环名称，因此 `coddy --remote`、脚本和内置 Web UI 不受影响，并且集群中继在调用节点之前会丢弃其服务页面的 `Origin`。要通过另一个主机名访问回环服务器，或从另一来源的页面调用它，请配置凭据或在 `httpserver.cors` 中列出该来源。配置了令牌或登录后，则由身份验证门决定。`httpserver.allow_insecure: true` 表示服务器故意开放，并关闭两种拒绝：局域网上的部署，或在前方自行完成用户登录的代理。扩展的端点（`/browser/v1/`）保留自己的门。

### Web UI 登录（可选）

持有者令牌保护 API，但不给浏览器提供进入方式：SPA 显示 `Unauthorized (401)`，且没有可输入令牌的字段。登录表单是浏览器为同一道门提供的凭据。它**默认关闭**，未提及它的配置行为与之前完全一致。

```yaml
httpserver:
  host: 0.0.0.0
  auth_token: "${CODDY_HTTP_TOKEN}"   # unchanged: for API clients
  login:
    enable: true
    user: "pasha"
    password_hash: "$$argon2id$$v=19$$..."   # written by `coddy serve set-password`
    session_ttl_hours: 720                   # 0 = until the browser closes
```

使用命令而非手动编写账户：

```bash
coddy serve set-password --user pasha
```

它会要求输入两次密码（当标准输入是管道时，则提示一次），存储 argon2id 哈希并开启表单，原地编辑 `config.yaml`，以便注释和键顺序得以保留。手动输入的哈希需要每个 `$` 都加倍 - `$$argon2id$$v=19$$...` - 因为此文件在加载时会将 `$NAME` 展开为环境引用；`coddy -t` 在发现不再能解析的哈希时会说明这一点。

账户也可以完全存在于环境中，这是容器或 systemd 单元的途径：`CODDY_HTTP_USER` 和 `CODDY_HTTP_PASSWORD`（明文，在服务器启动时哈希，绝不写入文件）自行启用表单，就像 `CODDY_HTTP_TOKEN` 在没有 `auth_token` 的情况下启用持有者门一样。`$CODDY_HOME/.env` 是它们的自然归属。当文件和环境中都带有账户时，环境优先，且文件中显式的 `login.enable: false` 会在变量仍设置的情况下关闭表单。没有 `--login-password` 标志：命令行上的密码在 `ps` 中可见。

三个路由提供表单，且三者无需凭据即可访问，因为它们是穿过这道门的方式：

| 路由 | 作用 |
|---|---|
| **`GET /coddy/auth/me`** | 对已登录浏览器提供 `login_required`、`auth_required`、`authenticated` 以及 `user` / `expires_at`。SPA 在启动时调用它以在登录屏幕和应用之间选择。 |
| **`POST /coddy/auth/login`** | `{user, password}`。成功时设置一个 `HttpOnly`，`SameSite=Strict` `coddy_session_<host digest>` cookie（当请求通过 TLS 到达或通过发送 `X-Forwarded-Proto: https` 的代理到达时为 `Secure`），存活 `session_ttl_hours`；使用 `0` 时浏览器在关闭时丢弃它，服务器在 30 天后使自己的记录过期。名称携带请求所指向主机的摘要，因为 cookie 不按端口限定作用域：否则同一台机器上的两个 Coddy 服务器（例如一个中继和其背后的节点）会在每次登录时互相登出。 |
| **`POST /coddy/auth/telegram`** | `{init_data}`：作为 Telegram 机器人 Mini App 打开的 Web UI 的启动数据。签名根据机器人的令牌校验（启动数据最多一小时旧，每次启动一次）。`${CODDY_HOME}/telegram-launches.json` 记录跨重启接受的启动。重用已接受的启动数据返回 401。重放记录存储失败返回 500，且不签发会话或 cookie。在记录被替换之前的失败不会将该启动标记为已使用，因此在修复存储后用相同的启动数据重试。如果替换后目录同步失败，该启动可能已被标记为已使用，并在内存中保持防重放保护；如果重试返回 401，请再次打开 Mini App。只有 `gateways.telegram.admins` 中的用户被登录，使用 HttpOnly、`SameSite=Strict` 的 `coddy_tg_session_<host digest>` cookie，它打开表单 cookie 所打开的内容，同样位于仅令牌门之后，并在令牌变化、机器人被禁用或该人不再是管理员时结束。其他人返回 403。当路由可用时，`GET /coddy/auth/me` 表示 `telegram_login: true`。 |
| **`POST /coddy/auth/browser`** | `{ticket}`：[适用于浏览器的 Coddy](../features/browser.md) 的侧边面板通过其套接字（`panel/open`）获得并加载 Web UI 的一次性票据。在一分钟内有效，用于一次登录，并绑定其签发时的扩展密钥；成功时返回 HttpOnly、`SameSite=Strict` 的 `coddy_browser_session_<host digest>` cookie，它打开表单 cookie 所打开的内容，同样位于仅令牌门之后，并在 `browser.token` 改变或 `browser.enable` 关闭时结束。对于未知、已使用或已过期的票据返回 401。当扩展的端点开启时，`GET /coddy/auth/me` 表示 `browser_login: true`。 |
| **`POST /coddy/auth/logout`** | 在服务器上丢弃会话并使 cookie 过期（Mini App 的也如此）。幂等。 |

登录后，cookie 会打开每个 `/v1/*` 和 `/coddy/*` 路由，包括 SSE 流 - 同源的 `EventSource` 会发送 cookie，因此无需 `?access_token=`。cookie 为 `SameSite=Strict`，这在此处没有任何成本（页面本身是公开的，且已加载页面所做的每次调用都是同源的），意味着浏览器绝不会将其附带在其他站点引发的请求上。除此之外，**改变状态**的 cookie 身份验证请求会以 `403` 拒绝，除非 `Sec-Fetch-Site` 表示 `same-origin`（或 `none`）或 `Origin` 与请求主机匹配 - 因此用 cookie 驱动此 API 的脚本必须发送 `Origin` 头，或者更好的是出示持有者令牌。持有者请求从不接受该检查，这正是 `coddy --remote`、编辑器和中继保持不变工作的原因。

错误密码和未知用户返回相同的 `401` 和相同的正文，以恒定时间比较。来自同一地址的重复失败会被逐渐更慢地应答，从 250 毫秒倍增到五秒的上限，并在十五分钟安静后遗忘；尝试在判断之前被计数，因此一起到达的一阵请求会承受不断增长的等待，而不是每个成员都读到干净的状态。回环从不限流，因此机器无法将自己锁在自己智能体之外 - 而且由于该豁免否则会覆盖反向代理后面的整个互联网，*来自*回环的请求在存在时按 `X-Forwarded-For`（或 `X-Real-IP`）中的地址计数。来自其他任何地方的请求按其实际来源计数，忽略头。会话保存在内存中：配置重载（例如从页面保存设置）会保留它们，而重启进程会结束它们。轮换密码或重命名账户会在下一次请求时结束其打开的每个会话，无需手动使任何东西失效。存储上限为 512 个活动会话，最旧的优先。

`GET /coddy/config` 绝不返回 `password_hash`；它报告 `httpserver.login_configured` 和 `httpserver.login_source`（`config` 或 `env`），并且从设置屏幕保存会保留哈希，就像保留 `auth_token` 一样。相邻的 `auth_configured` 按其字面含义（设置了持有者令牌），因此用密码关闭且没有令牌的服务器会在 `login_configured: true` 旁报告 `auth_configured: false`；当问题是"此服务器到底是否需要凭据"时，询问 `GET /coddy/auth/me`。文档继续描述文件，因此来自环境的账户绝不会被保存写入 `config.yaml`。

登录表单用于此来源。环境选择器仍然用持有者令牌访问**远程**服务器，因为此来源的 cookie 不会跨源传输。

关于 `${VAR}` 引用的一点说明。`login.user` 和 `login.password_hash` 像 `config.yaml` 中的其他每个值一样接受它们，并且像其他每个值一样在文件加载时展开 - 因此从设置屏幕保存会将**展开后的**值写回，把 `user: "${CODDY_HTTP_USER}"` 变成 `user: pasha`。此文件一直就是这样处理 `${VAR}` 的；如果目的是将凭据完全排除在文档之外，请使用 `CODDY_HTTP_USER` 和 `CODDY_HTTP_PASSWORD`，它们绝不会进入其中。

### 跨源访问与远程 UI

内置 UI 可以指向**远程** `coddy serve` 服务器（环境选择器切换 API 基础 URL 并发送远程的持有者令牌）。由于那是跨源调用，远程服务器必须选择加入 CORS：

```yaml
httpserver:
  auth_token: "${CODDY_HTTP_TOKEN}"
  cors:
    enable: true
    allow_loopback: true          # the laptop's own coddy serve, on any loopback address and port
    allowed_origins: ["https://my-ui.example"]   # exact origins elsewhere; or ["*"]
  remotes:                       # optional: offered in the UI environment selector
    - name: "prod box"
      url: "https://box.example:12345"
      token: "${PROD_BOX_TOKEN}"   # optional: the bearer the UI and the console present
```

当 `cors.enable` 为真时，允许来源的预检 `OPTIONS` 请求返回带有 `Access-Control-Allow-Origin`（回显来源，或在配置时为 `*`）、`Vary: Origin` 和 `Access-Control-Allow-Headers: Authorization, Content-Type, X-Coddy-Session-ID` 的 `204`；不允许的来源不接收 CORS 头。其 `Origin` 为 `null`（沙箱页面、`file://` 页面）的请求在除画布框架地址（[Canvas](#canvas)）之外的每个路由上都以 `403` 拒绝。当 `allowed_origins` 精确命名它、当 `allowed_origins` 包含 `"*"`，或当 `allow_loopback` 开启且来源为 `http` 或 `https` 且主机为回环（`localhost`、`*.localhost` 名称、`127.0.0.0/8` 或 `[::1]`）任意端口时，来源被允许。列表首先且按顺序读取，因此其中的 `"*"` 会使每个未被条目命名的来源（包括回环来源）都得到 `*` 应答；仅由 `allow_loopback` 允许的来源会被回显，绝不会扩大到 `*`。无论三者中哪一个允许页面，持有者身份验证仍适用于实际请求，且 `allow_loopback` 和 `"*"` 的安全性仅取决于该凭据。远程的令牌要么是其 `httpserver.remotes` 条目的 `token`（**`GET /coddy/config`** 会将其交给每个读取它的页面），要么是输入到 UI 的 **Connect to…** 表单中的令牌（UI 按远程客户端保留）。集群中继改为通过 `swarm.cors` 应答跨源页面（形状相同），UI 通过其公开的 **`GET /swarm/info`** 而非中继不提供的 **`/v1/models`** 来识别它。

由于 `EventSource` 无法跨源发送 `Authorization` 头，两个 SSE 订阅路由 - **`GET /coddy/sessions/{id}/composer-stream`** 和 **`GET /coddy/events`** - 也接受令牌作为 `?access_token=` 查询参数。没有其他路由这样做；在客户端可以设置头的地方优先使用头，因为查询令牌会进入代理访问日志。

## 内嵌 Web UI（**`-tags=http,ui`**）

- **`GET /`** 在链接时使用 **`http`** 设置 **`ui`** 的情况下，从 **`external/ui/`**（`go:embed`）提供 **`index.html`**、**`styles.css`**、**`app.js`** 和 **`events-worker.js`**（一个环境的标签页通过它共享 **`GET /coddy/events`** 的 SharedWorker），并一并提供使 Web UI 成为可安装应用的内容：Web 应用清单 **`/manifest.webmanifest`**（以 **`application/manifest+json`** 提供）、其图标 **`/icon-192.png`**、**`/icon-512.png`** 和 **`/icon-maskable-512.png`**，以及服务工作者 **`/sw.js`**，后者不缓存任何内容并显示 Web UI 的通知（[将 Web UI 安装为应用](../surfaces/web-ui.md#将-web-界面安装为应用)）。与外壳的其余部分一样，它们在 **`httpserver.auth_token`** 和登录表单之后是公开的，因为浏览器在任何人登录之前就会请求它们。对 **`/`**、**`/index.html`**、**`/app.js`**、**`/events-worker.js`**、**`/styles.css`** 以及这些文件的响应包含 **`Cache-Control: no-cache`**，因此在你重新构建二进制文件后，正常重载会拾取资源（固定 URL，无指纹）。页面按需加载的渲染器（Mermaid、KaTeX 及其字体）从 **`/chunks/`** 以内容哈希名称和 **`Cache-Control: public, max-age=31536000, immutable`** 提供。每个文件都携带其内容的 **`ETag`**，因此重新验证会不带正文地返回 **`304`**，并且文本文件（JavaScript、CSS、HTML、JSON、SVG、清单）会向接受它的客户端发送 **`Content-Encoding: gzip`** 和 **`Vary: Accept-Encoding`**；范围请求按其接受的编码应答。
- **仅 API 模式**：在配置中设置 **`ui.enable: false`**，即使编译了 **`ui`** 标签也运行不带 SPA 的服务器。此时 **`GET /`** 返回一个简短的纯文本通知（HTTP 404）而非 UI；每个 **`/v1/*`** 和 **`/coddy/*`** 路由继续工作，并在设置时继续要求 **`httpserver.auth_token`**。适用于其他 UI 连接的无头远程机器。
- 推荐的会话 URL 模式：**`#/s/<sessionId>`**（仅客户端历史）。对于 **`POST /v1/responses`** 和 **`POST /v1/chat/completions`**，发送带有满足服务器端验证（`internal/session/validate.go`）的 **`sess_<hex>`** 标识的 **`X-Coddy-Session-ID`**。
- 在 **`POST /v1/responses`** 和 **`POST /v1/chat/completions`** 上设置 **`X-Coddy-Session-Origin: print`** 会将请求创建的会话标记为一次性打印模式的一次运行（**`session.json`** 中的 **`origin: print`**），会话列表和选择器除非被要求（**`GET /coddy/sessions`** 上的 **`include_print`**、**`origin=print`**）否则会将其排除。这就是 **`coddy --remote <server> -p`** 与其创建其会话的提示词一起发送的内容。服务器仅在请求创建会话时记录它，绝不会在已存在的会话上记录，并且在创建任何内容之前以 **`400`** 应答任何其他值（[会话](../features/sessions.md#标签与归档)）。没有 **`X-Coddy-Session-ID`** 的直接调用不创建会话，因此该头在那里不标记任何内容。
- **`GET /coddy/sessions`**、**`PATCH /coddy/sessions/{id}`** 和其他 **`/coddy/sessions/{id}/...`** 路由**仅**通过 **`{id}`** 路径段标识会话（OpenAPI 中没有重复头；客户端仍可发送 **`X-Coddy-Session-ID`**，但对于那些 URL 它不用于选择资源）。
- 内置 UI 使用 **`stream: true`** 调用 **`POST /v1/responses`**。在会话打开和重连时，它读取 **`GET /coddy/sessions/{id}/activity`** 和 **`GET /coddy/sessions/{id}/queue`**，而不需要在过滤或分页的 **`GET /coddy/sessions`** 列表中有一行。服务器活动独立于本地流读取器驱动停止和队列控件；丢失读取器并不能证明轮次已结束。现有的 **`GET /coddy/sessions/{id}/composer-stream`** 中继（SSE）让 UI 重放已为运行中轮次发送的字节，并继续接收实时块，直到 **`data: [DONE]`** 或错误事件。启动新的 **`POST /v1/responses`** 会在客户端取消该中继订阅。对于 ReAct（**`model`** **`agent`**、**`plan`** 或 **`ask`**），它会发送可选的 **`metadata.model`**，其中包含选定的 YAML **`models[].model`** **`id`** 和可选的 **`metadata.runPlanSlug`**，以实现保存的设计计划（ACP **`session/prompt`** 上的 **`coddy.dev/runPlanSlug`**；当 **`model`** 为 **`ask`** 时在轮次开始前以 **`409`** 应答）（来自 **`GET /v1/models`**，除 **agent**、**plan** 和 **ask** 配置文件之外的每一行）；默认是其在 **`coddy_llm_model`** 中记住的选择，否则是按字母顺序的第一行。每个轮次还携带 **`metadata.surface: "webui"`**，它为那一轮提供一个系统提示词块，告诉模型 Web UI 将 **`mermaid`** 和 **`svg`** 围栏绘制为图片并排版 LaTeX（**`external/httpserver/webui_prompt.go`**；在 **`POST **`id`**、**`kind`**、**`label`**、**`agent`**、**`status`**、**`exitCode`**、**`durationMs`** 和 **`error`** 命名每一个，并且该轮次的第一条消息以相同的任务持久化，因此没有客户端会将指令显示为用户气泡，无论是实时还是重载后；内置 UI 在其位置不显示任何内容，任务行显示 **`woke_agent`**（见 **`docs/features/background-tasks.md`**）。**`coddy_meta`** JSON 遵循紧接在 **`data: [DONE]`** 之前的通常规则；对于 agent/plan/ask 轮次，它还携带 **`stop_reason`**（`end_turn`、`cancelled`、`max_turns`……），以便远程客户端恢复 ACP 停止原因。以设置命令开头的提示词会在轮次之前应用它们（[会话设置](../features/session-settings.md)）；仅命令的提示词不运行轮次，将每次更改的通知作为应答流式传输，并以 **`coddy_meta`** **`settings_only: "true"`** 结束，因此客户端可以丢弃其为该交换绘制的行：其中没有任何内容保留在对话记录中，更改显示在会话的 **`settings`** 中。**`event: session_settings`** 在流期间会话设置变化时（命令、权限对话框的会话开关、模型的 **`switch_model`**）携带设置快照，仅当智能体自行做出更改时才携带 **`notice`**。**`event: session_goal`** 在流期间会话目标变化时（**`GET /coddy/sessions/{id}/goal`** 的形状 - 由 **`/goal`** 设置、检查、继续、暂停、清除）携带该目标，而 **`event: goal_turn`** 开启会话监督器启动的每个轮次（**`kind`** 启动、继续、恢复、重新开始或收尾，**`limit`**、**`objective`**、**`reason`**、**`remaining`** 的 **`index`**）；该轮次的第一条消息以与 **`goal_turn`** 相同的标记持久化，因此内置 UI 显示一行目标行而非指令文本。输入框中的 **Stop generation** 总是调用 **`POST /coddy/sessions/{id}/cancel`**，其 **`{"continue_queue":true}`** 和 **`X-Coddy-Session-ID`** 与 **`{id}`** 匹配。发送后，UI 立即在其自己的该轮次流式 **`fetch`**（POST 或中继）上触发 **`AbortSignal`**：浏览器跨所有标签页对每个主机保持六个 HTTP/1.1 连接，否则取消可能会等待该流所持有的连接。轮次在没有流的情况下继续运行；取消失败会显示错误，保留运行控件以供重试，并通过 **`GET /coddy/sessions/{id}/composer-stream`** 重新加入该轮次。**`queueContinued: true`** 确认已接受的队列继续，而非完成的答案；UI 重新附加到相同的轮次代次，而无需等待新的 **`turn_started`**，并且从不自行排空或重新提交排队的消息。没有该标志时，成功确认完全取消，而 **`turn_ended`** 或报告空闲的新活动快照确认完成。默认完全取消对应智能体轮次的 ACP **`session/cancel`**（直接 **`models[].model`** 完成的 **`TurnCtx`** 传播使用相同的取消钩子）。流中取消仍会**持久化**该轮次累积的助手 **`content`**；**`GET /coddy/sessions/{id}/messages`** 可能短暂落后于该写入，因此 SPA 将获取的行与其每会话影子或屏幕对话记录**合并**（**`external/ui/src/ui/chat/transcriptServerSnapshot.ts`** 中的 **`mergeTranscriptPreferLocalSuffix`**）。多个会话可以并行流式传输（**`streamMutationBase.ts`** 中的 **`pickStreamMutationBase`** 使 SSE 变更按 **`X-Coddy-Session-ID`** 限定作用域）。
- **生成速度**：`turn_progress.tokensPerSecond` 是可选的。实时窗口每五秒刷新一次，并按模型调用重置。最后一帧有 `completed: true`，包括取消和失败，并且仅在至少一次模型调用具有可测量的生成间隔时携带轮次平均值。会话的 `uiLog` 将其保存为 `generation`，带有 `outputTokens`、`tokensPerSecond` 和 `elapsedMs`，即轮次运行的时长。活动快照将实时窗口暴露为 `turnTokensPerSecond`。阻塞（非流式）提供商、ACP 智能体模型以及以单个输出块交付的调用对速度平均值不贡献令牌或时间；输出计数仍包括它们。没有可测量的调用间隔时，实时输出计数仍然可用，但速率被省略，并且不保存生成标题。当存在平均值时，其保存的标题将来自所有调用的输出令牌总数与仅跨已测量调用的速率配对。保存的平均值是仅 UI 的 `uiLog` 条目，带有 `generation: {outputTokens, tokensPerSecond}`；它们绝不会进入模型历史。
- 在全新聊天（轨道中尚无会话）的第一条用户消息上，UI 与 **`/v1/responses`** 并行地 **`POST`** **`/coddy/describe`**，以新聊天的 **`X-Coddy-Session-ID`** 及其文件夹作为 **`cwd`**，以便该工作区的斜杠命令被描述给模型。在调用落定之前（一个答案、空的 **`short`**、失败或 30 秒，之后迟到的名称仍会落定），标题和聊天的历史行显示闪烁的占位符而非第一条消息。当 **`short`** 到达时，标题和会话列表标题**立即**更新；**`PATCH /coddy/sessions/{id}`** 仍在头暴露规范会话 ID 后运行一次（如果持久化落后于 describe，则短暂重试 PATCH），携带相同答案所提议的 **`tags`**，因此命名和归档新聊天在它们之间只花费一次模型调用。该 PATCH 携带 **`titleIfUnpinned`**，这使标题成为建议：在第一轮中已被命名的会话（在聊天头中，或由智能体的 **`session_describe`** 工具）保留其名称，只有标签落定。
- 内置 UI 在 **`#/settings`** 暴露**设置**。它加载 **`GET /coddy/config/schema`**（编辑器的 JSON Schema）和 **`GET /coddy/config`**（当前值，包括 **API keys**、可选的每提供商 **`proxy`** URL 以及 **`gateways.telegram.token`** 机器人令牌），然后在保存时加载 **`POST /coddy/config/validate`** 和 **`PUT /coddy/config`**。提供商表单的 **Models** 列表和逻辑模型表单的 **Context window** 字段以表单持有的提供商行调用 **`POST /coddy/providers/models`**（自动获取会省略 **`api_key_command`**；只有刷新控件发送它），因此尚未保存的提供商（例如 OAuth 设备登录后立即）也会列出其模型；逻辑模型表单还在 **Fetch reasoning levels** 后面调用 **`GET /coddy/config/reasoning-levels`**，它用为正在编辑的模型 ID 检测到的层级填充 **`models[].reasoning_levels`**（其指向的提供商行的类型作为 **`provider_type`** 发送，因此未保存的提供商也会被尊重）。**`gateways`** 块通过此 API 往返，因此在 UI 中编辑设置不再丢弃 Telegram 配置。这些路由没有单独的身份验证 - 仅在受信任网络上暴露 **`coddy serve`**。

- **轮次进度**是名为 **`turn_progress`** 的 SSE 事件，带有 **`startedAt`**（RFC3339，轮次被接纳的时间）、**`elapsedMs`**（同一事实的持续时间形式，因此时钟与服务器不一致的客户端从其自己的现在减去它）、**`outputTokens`**、**`estimated`** 以及仅在第一帧上的 **`phase: "preparing"`**。第一帧在轮次被接受时立即发送，早于它引入其 MCP 服务器并等待其模型的上下文窗口 - 冷服务器需要数秒 - 内置 UI 将其读作"Preparing the session…"；循环自身的报告不携带阶段。它在循环开始时再次发送 - 零令牌，客户端将其渲染为时钟和"waiting for the model" - 在模型调用流式传输期间最多每秒一次，并在每次调用之后。**`outputTokens`** 汇总提供商为该轮次已完成调用报告的内容，以及正在进行的调用已流式传输的估计值（字符数 / 4），工具调用参数片段在到达时即被包含（或对于没有片段的提供商在调用完成后）；**`estimated`** 在估计值是数字的一部分时为真，并且对于不报告用量的提供商保持为真。输入框中继不会重放客户端对话记录快照已覆盖的帧，因此迟加入的客户端从 **`GET /coddy/sessions/{id}/activity`** 读取相同的数字。OpenAI 严格 **`POST /v1/chat/completions`** 流像每个命名事件一样用 SSE 注释替换它。
- **文件输入进度**：`tool_call_update` 与 `status: "pending"` 可能为 `write`、`edit` 和 `apply_patch` 携带 `_meta.coddy.toolInputProgress`。字段：`path`（上限 512 字节，接收前为空）、`bytes` 和 `lines`（已接收的解码内容）、`argumentBytes`（已接收的原始 JSON 字节）以及 `preview`（最新六行，最多 1 KiB，可能是不完整的行）。这是草稿，绝不是可执行参数或工具结果。更新被限流为每次调用每秒五次，外加最终刷新。终态状态取代草稿。客户端在显示模型生成的路径或预览之前必须清理终端控制字符。OpenAI 严格流像其他工具更新一样抑制此命名事件。
- **调用返回的图片**：返回图片的调用的 `completed` `tool_call_update`（在 PNG、JPEG、GIF 或 WebP 文件上为 **`read`**，或结果携带图像块的 MCP 工具）携带 `_meta.coddy.images`，每张图片一个条目：`name`（文件的名称，MCP 工具的图片为 `<server>-<tool>-<n>`）、`mime_type`（发送给模型的类型）、`asset`（保存在会话 `assets/` 中的副本）、`url`（**`GET /coddy/sessions/{id}/assets/{name}`**）以及当生成缩略图时的 `preview_url`。重载后，**`GET /coddy/sessions/{id}/messages`** 的工具行将相同的图片携带为 **`files`**。内置 UI 在调用的行下方预览它们；图片的字节绝不会在事件中传输。

在 `stats.json` 中，当该总数所代表的任何调用具有未知用量时，`tokenUsageTotal.usageKnown` 为假；`tokenUsageByTurn[].usageKnown` 描述其调用。真标志允许显式报告的零。较早的统计省略该标志：会话列表返回其存储的数字，包括零。对话记录导出则包括带标志的已知总数（包括零），或带有正计数器的无标志总数；它省略未知总数和无标志的全零总数。

- **当前上下文用量**是一个单独的命名 SSE 事件 **`usage_update`**，带有 **`used`** 和 **`size`**。它在手动或自动压缩后重新发出。**`token_usage`** 仍然是已完成的模型调用计数器，不用作上下文窗口分子。

### 壁纸画廊

![本地壁纸上传、在服务器文件和浏览器选择之间经过身份验证的图像读取和删除](../../assets/diagrams/local-wallpapers.png)

*上传添加或重用服务器文件；浏览器保持自己的选择。清除将文件留在原处；确认删除移除服务器文件。*

画廊将图片直接存储在所选服务器上的 `${CODDY_HOME}/wallpapers`（通常为 `~/.coddy/wallpapers`）内。它不联系外部图片服务。列出缺失的目录会得到 `200` 及 `{"wallpapers":[]}` 而不创建它。上传在需要时创建目录，模式为 `0700`，新文件模式为 `0600`。链接的画廊目录、该路径上的非目录或其他存储失败会得到 `500`，而非空画廊。文件访问保持在该目录内，拒绝链接和非常规文件。

在配置了主目录的首次 HTTP `Serve` 启动时，在监听之前，Coddy 在画廊之外认领 `${CODDY_HOME}/.wallpapers-initialized`。如果画廊不存在，Coddy 以模式 `0700` 创建它，并以模式 `0600` 独家复制四张内嵌图像：`dunes.png`、`hills.png`、`night.png` 和 `coddy-purple.png`。不会自动选择背景。现有的画廊（无论是否为空）保持原样，并记录决定。一旦存在常规标记，Coddy 不恢复已删除的文件或已删除的画廊。标记在复制之前被认领，因此中断的复制可能留下部分包且不重试。初始化错误记录为警告；HTTP 服务器继续启动。包是内嵌的，无需外部下载。此启动操作与 `GET` 分开，后者绝不创建目录。

`GET /coddy/wallpapers` 按名称排序（区分大小写比较）返回 `{"wallpapers":[{"name":"landscape.png"}]}`。它列出目录顶层具有已识别图像头的常规文件，省略隐藏文件、链接、子目录、特殊文件和未识别的图像。读取画廊或图片时的 I/O 失败使列表以 `500` 失败。条目仅包含名称，不包含文件系统路径。

`GET /coddy/wallpapers/{name}` 在识别其图像头后从安全打开的常规文件流式传输原始字节。服务器从该头检测媒体类型，而非扩展名或客户端提供的 `Content-Type`。它不施加文件大小、尺寸、像素或帧限制。它既不解码像素也不在流式传输之前将整个文件读入内存。头识别不能证明浏览器可以解码整个图像；不可读的图片在浏览器中失败。两个 GET 路由都支持 `HEAD` 并发送 `Cache-Control: no-store`。图像响应发送检测到的 `Content-Type`、`Content-Length` 和 `X-Content-Type-Options: nosniff`。

`POST /coddy/wallpapers/{name}` 接受请求正文中的原始文件字节，而非多部分数据或 base64。请求可以声明 `Content-Type: image/png`；服务器识别图像头而非信任该值。将 `name` URL 编码为一个路径段。对于每个命名路由，它必须非空、有效的 UTF-8，不含前导点、斜杠、反斜杠、冒号或控制字符。

```http
POST /coddy/wallpapers/landscape.png HTTP/1.1
Authorization: Bearer <token>
Content-Type: image/png

<raw file bytes>
```

服务器在写入临时文件时计算 SHA-256，具有有界工作内存且无图像大小上限。如果上传的字节已存在于任何画廊名称下，它返回该现有名称及 `200` 和 `created: false`。否则它存储新文件并返回 `201` 和 `created: true`。如果请求的名称属于不同的字节，它选择带后缀的名称而不覆盖现有文件。响应始终命名实际存储的文件。临时文件在取消或错误时移除。

不覆盖的原子发布需要文件系统对硬链接的支持。如果文件系统不支持它们，服务器返回存储错误而非回退到可能覆盖的操作。并发上传的哈希去重在单个服务器进程内协调。共享主目录的独立进程不协调该比较，但目标名称绝不覆盖。

```json
{"wallpaper":{"name":"landscape.png"},"created":true}
```

`DELETE /coddy/wallpapers/{name}` 移除命名的服务器文件并返回无正文的 `204`。[Web UI](../surfaces/web-ui.md#壁纸) 仅在缩略图的确认对话框被接受后发送它。成功后，如果该图片被选中，它还清除此浏览器的背景；删除另一张图片使选择不变。单独的清除背景控件仅更改浏览器本地选择，绝不删除服务器文件。

读取、上传和删除使用[正常的 API 身份验证策略](#身份验证可选)，配置身份验证时使用持有者头或浏览器的登录 cookie。没有路由接受 URL 查询令牌。Web UI 对所有操作使用所选环境，包括远程服务器或通过集群中继到达的节点。显式的文件选择器操作上传到该服务器。加载先前保存的浏览器本地图片不会上传它。上传保留现有背景；未选择时，UI 选择上传的图片。浏览器本地持久化遵循[壁纸存储规则](../surfaces/web-ui.md#壁纸)。

| 状态 | 画廊操作失败 |
| --- | --- |
| `400` | 无效的文件名。 |
| `404` | 缺失的图片、链接或另一种非常规文件。 |
| `415` | 无效或未识别的图像头。 |
| `500` | 画廊或图片存储失败。错误消息不包含文件系统路径。 |

```json
              "tokensOut": [null, 2100.0], "turnsRunning": [1, 2], "tasksUnfinished": [3, 3]}}}
```

每个系列在真实文档中持有 240 个点，此处缩短。成员为 camelCase，如同 **`/coddy/info`**。可选成员在为空、假或零时被省略，绝不作为零发送，因此缺失成员意味着没有或未测量。

| 成员 | 存在 | 含义 |
|--------|---------|---------|
| **`object`**、**`generatedAt`** | 始终 | **`coddy.status`**，以及服务器构建文档的时间（RFC 3339，UTC）。 |
| **`build`** | 始终 | **`version`**（**`coddy -v`** 打印的内容）、**`goVersion`**、**`os`**、**`arch`**；当二进制文件知道时为 **`revision`** 和 **`tags`**（构建标签）。 |
| **`process`** | 始终 | **`startedAt`**；**`startedBy`**：**`systemd`**（**`CODDY_SERVE_ROLE=service`**）、**`daemon`**（**`coddy serve --daemon`** 的工作者）或 **`foreground`**，启动时读取一次；**`configFile`**，加载的文件及 OS 主文件夹（非 **`CODDY_HOME`**）书写为 **`~`**。 |
| **`subsystems`** | 始终，可能为空 | 配置启用或进程仍运行的每个子系统一行，按声明顺序：**`kind`**；**`state`**（**`running`**、**`starting`**、**`stopped`**、**`retained`**）；运行中的监听器的 **`address`**；保存的地址不同时的 **`pendingAddress`**；仅在 **`metrics`** 行上的 **`credential`**（**`token`** 或 **`none`**），绝无令牌。 |
| **`restartRequired`** | 仅 **`true`** | 保存的更改等待没有任何东西会自行执行的重新启动（**`coddy_restart_required`** 背后的条件）：移动的监听地址（由行的 **`pendingAddress`** 命名），或在没有会话存储启动的进程中启用了运行轮次的界面。 |
| **`restartRefused`** | 设置时 | 受监督的进程为何不会重新启动到保存的配置：新进程所运行的检查的消息，该检查拒绝它。 |
| **`turns`** | 始终 | **`running`**，有轮次运行的会话；**`oldestSeconds`**，最长者的年龄，仅在有一个运行时。 |
| **`prompts`** | 非空时 | 等待人应答的提示词：**`permission`** 和 **`question`**，各自仅在大于零时存在；两者都为零时缺失。 |
| **`tasks`** | 非空时 | 按种类（**`command`**、**`agent`**、**`server`**）和状态（**`queued`**、**`running`**）的未完成后台任务。 |
| **`disk`** | 读取时 | 持有会话的磁盘的 **`availableBytes`** 和 **`sizeBytes`**。 |
| **`unavailable`** | 非空时 | 无法读取的块：目前为 **`"disk"`**，当读取失败或平台没有而存在会话存储时。 |
| **`attention`** | 非空时 | 需要人的内容，按下表顺序。 |
| **`metrics`** | 带有 **`metrics`** 标签 | 是否设置 **`metrics.enable`**；在没有该标签构建的二进制文件中缺失。**`providers`**：**`name`**、**`attempts`** 和 **`failures`**（**`CoddyProviderFailing`** 计算的四个结果）自启动以来、**`meanSeconds`** 仅在有一次尝试后、**`lastFailureAt`** 和 **`lastOkAt`**（总数最后上升的 15 秒样本）。**`series`**：**`stepSeconds`**（15）、**`end`**，以及恰好 240 个点的七个数组，最旧的优先，最后一个在 **`end`**；**`null`** 是间隙。**`attemptsOk`**、**`providerErrors`**、**`tokensIn`** 和 **`tokensOut`** 为每分钟，**`attemptSecondsMean`** 以秒为单位，**`turnsRunning`** 和 **`tasksUnfinished`** 为仪表。采样器每 15 秒从导出器自己的计数器填充它们；它们在内存中存活一小时，重启后从空开始。 |

**`attention`** 项为 **`{"code": ...}`**，加上 **`subsystem`**、**`provider`** 或 **`relay`** 及 **`offlineSince`**（在它命名一个时）：

| 代码 | 触发条件 |
|------|-------------|
| **`restart_required`** | 设置了 **`restartRequired`**。 |
| **`disk_low`** | 会话磁盘剩余不足 512 MiB（固定值，**`CoddyDiskLow`** 使用的那个）；Web UI 将零表述为 **Disk full**。 |
| **`subsystem_down`** | 一行为 **`stopped`**（绝不在 **`starting`** 时），包括导出器单独失败时；携带 **`subsystem`**。 |
| **`provider_failing`** | 仅在 **`metrics`** 时：在过去 15 分钟内，提供商的失败上升且此后没有成功的样本；携带 **`provider`**。 |
| **`swarm_join_down`** | 此进程到父中继的注册（**`swarm.join`**）已离线 5 分钟，即 **`CoddySwarmJoinDown`** 的条件；每个中继主机一项，带有 **`relay`** 和 **`offlineSince`**（RFC 3339，UTC）。注册让位于同一进程中继的时间不计算。 |

列表按 **`restart_required`**、**`disk_low`**、**`subsystem_down`**（行顺序）、**`provider_failing`**（提供商名称顺序）、**`swarm_join_down`**（中继主机顺序）排序。设置徽章上的数字是其长度：浏览器不应用自己的规则。

文档携带一个路径 **`process.configFile`**。它不携带会话 ID 或标题、工作区文件夹、提示词、工具参数、错误文本、聊天 ID、用户名或令牌：只有构建事实、计数、持续时间、进程监听的地址以及配置中的提供商名称和中继主机，这些是 **`/metrics`** 允许作为标签的。

### 停止和队列控件快照

在会话打开和重连时，客户端为所选 ID 读取 **`GET /coddy/sessions/{id}/activity`** 和 **`GET /coddy/sessions/{id}/queue`**。这些读取不依赖于过滤或分页历史列表中的匹配行、活动轮次读取器或另一个队列变更。UI 和交互式远程控制台独立于它们自己的提示词/流生命周期跟踪服务器活动。浏览器在其自己的 POST 接纳期间跳过两个水合读取，并在声明空闲之前通过新的 REST 确认与待处理或已接纳 POST 重叠的 **`turn_ended`**。

对于 **`continue_queue: true`**，资格要求在同一进程中运行且带有等待消息的普通 **`agent`**、**`plan`** 或 **`ask`** 配置文件提示词运行。直接完成、保存的计划运行、权限恢复和监督器命令改为使用完全取消，空队列也是如此。已接受的继续仅取消当前运行的子上下文，等待它展开并落定部分助手内容和工具结果，然后按原始 FIFO 顺序将所有预留消息作为单独的用户行附加，无论队列模式如何。重复项和保留的图片保持不变。新的子运行在相同的接纳和轮次代次下应答它们，一个写入者且没有空、合成或组合的用户提示词。

预留截止将那一批与后来的排队消息分开，后者在下一个循环边界遵循正常规则。在第一个已接受批次被读取之前第二次停止优先作为完全取消并保留该未读批次。外部取消、错误和关闭绝不触发自动继续。未接受的队列消息保留默认取消规则，等待状态保持短暂的进程内存。浏览器保持其早期读取器中止和代次守卫；**`queueContinued: true`** 使其通过 **`composer-stream`** 重新附加到相同的代次而无需等待另一个 **`turn_started`**。客户端绝不自行排空或重新提交队列。

会话管理器的 **`QueueSnapshot`** 在一个锁下读取队列列表及其 **`version`**。队列 HTTP 响应（**GET**、**POST**、**PATCH** 和 **DELETE**）和 **`message_queue`** 事件使用该对，因此响应无法用较新的版本标记较旧的列表。普通交付保持每个会话的最高版本。对于浏览器重启恢复，新的队列 GET 在请求之前捕获交付修订和恢复纪元。浏览器拒绝被任何队列交付跨越的快照；否则它可以建立较低的版本，包括 **`0`**。该恢复推进本地纪元并拒绝在较早纪元中捕获的变更响应和自身/中继流队列帧。重放的 **`turn_started`** 通知不清除等待列表也不重置其版本。

这些控件保持非交互式提示词处理和权限/问题所有权不变，并且不将远程控制台附加到另一个客户端的活动对话记录。共享队列需要同一 **`coddy serve`** 进程的客户端；仅共享会话目录的单独本地控制台或 ACP 进程保留单独的队列和应答通道。跨进程取消仍使用捆绑包的取消标记。

**`POST /v1/chat/completions`** 和 **`POST /v1/responses`** 默认都将请求正文限制为 **512 MiB**，可通过 **`httpserver.max_body_bytes`** 配置。过大的正文返回 **413** 及 **`error.code: "request_too_large"`**。**`/v1/*`** 上的错误携带 **`error.message`**、**`error.type`**、**`error.code`** 和 **`error.param`**；最后两个可能为 null。提供商 HTTP 状态在可用时作为 **`error.upstream_status`** 包含。服务器错误隐藏内部细节。

Chat Completions SSE 错误在提供商命名重试延迟时还以秒为单位携带 **`error.retry_after`**。打开的 SSE 响应无法设置新的 **`Retry-After`** 头。另一个 Coddy 作为其提供商时，Coddy 客户端从此错误帧保留状态和重试延迟。

在 **`POST /v1/chat/completions`** 上，**`developer`** 角色被视为 **`system`**。直接请求在支持的提供商上接受 0 到 1 的 **`top_p`**。不支持的顶级和嵌套消息字段以 **400** 拒绝，包括消息 **`name`** 和 **`image_url.detail`**；**`error.param`** 标识字段路径。非 null 的 **`stream_options`** 要求 **`stream: true`**。直接请求拒绝 **`metadata.reasoning`**，即使为 null；改用 **`reasoning_effort`**。配置文件还拒绝生成选项和客户端工具。

### 两种流方言

带有 **`stream: false`** 的 **`POST /v1/chat/completions`** 请求在提供商报告令牌计数时返回带有 **`usage.prompt_tokens`**、**`usage.completion_tokens`** 和 **`usage.total_tokens`** 的 JSON。智能体、计划或询问轮次汇总其自己智能体循环的模型调用；其生成的子智能体（在其子智能体的任务行上计数）和压缩的调用不包括在内。当提供商报告缓存的输入令牌时，**`usage.prompt_tokens_details.cached_tokens`** 携带它们；Anthropic 单独的未缓存、缓存写入和缓存读取计数都包含在 **`prompt_tokens`** 中。如果提供商不提供计数，JSON 省略 **`usage`**，以便客户端可以区分未知用量和零用量。

配置文件轮次有两种流方言，由端点选择。带有 **`stream: true`** 的 **`POST /v1/chat/completions`** 是第三方客户端指向的界面（VS Code Copilot 通过 `chatLanguageModels.json`、openai SDK、任何逐字解析 `chat.completion.chunk` 的东西），因此它是严格的 OpenAI 契约且别无其他：第一个块带有 **`delta.role`** `assistant`；**`delta.content`**、**`delta.reasoning_content`** 和 **`delta.tool_calls`** 增量，每个选择带有 **`finish_reason: null`**；最终块的 **`finish_reason`** 为 **`stop`**，当轮次以 **`max_turns`** / **`max_tokens`** 结束时为 **`length`**，当直接模型调用了客户端工具之一时为 **`tool_calls`**，或当提供商的内容过滤器截断了直接答案时为 **`content_filter`**；在 **`stream_options.include_usage: true`** 和提供商计数器可用的情况下，还有一个块带有空的 **`choices`** 数组和轮次的 **`usage`**（**`prompt_tokens`**、**`completion_tokens`**、**`total_tokens`**，按与 JSON 答案相同的规则从提供商自己的计数器汇总该轮次的模型调用，仅当它报告缓存输入时才有 **`prompt_tokens_details.cached_tokens`**）；然后是 **`data: [DONE]`**。其上不出现任何命名的 **`event:`** 帧 - 这样的客户端会将一个读作没有选择的块 - 不过每个在其位置留下 SSE 注释，因此连接在经过工具阶段时保持与轮次一样繁忙；没有产生文本的轮次仍打开并完成一个选择，因为从未完成选择的流正是 VS Code 报告为"Response contained no choices."的内容。带有 **`model: agent`**、**`plan`** 或 **`ask`** 的 **`POST /v1/responses`** 是 coddy 自己的通道，由 SPA、远程控制台（**`--remote`**、**`coddy acp --remote`**）和集群中继读取：相同的块加上下方每个命名事件，**`coddy_meta`** 最后。

  **`POST /v1/chat/completions`** 上的直接 **`models[].model`** ID 是 coddy 代表提供商，客户端带来它会带给提供商的内容。其 **`tools`**（OpenAI 函数工具）按原样提供给模型；**`tool_choice`** `none` 扣留它们，`auto` 将选择留给模型；其他值被拒绝。模型进行的调用在流上以 **`delta.tool_calls`** 块返回 - 每次调用一个块，参数完整，**`index`** 计算调用次数 - 并在 JSON 答案上以 **`message.tool_calls`** 返回，带有 **`finish_reason`** **`tool_calls`**；客户端运行工具，重放带有其 **`tool_calls`** 的助手消息，并在 **`tool_call_id`** 下以 **`tool`** 消息应答，该请求可以以工具消息结束。共享现有会话 ID 的直接完成与配置文件轮次使用相同的独占轮次锁：繁忙的会话在其对话记录更改或联系提供商之前返回 **`409`**。消息 **`content`** 可以是字符串、`null` 或部分数组：**`text`** 部分被连接，**`image_url`** 部分（数据 URL 或 https 地址）到达其 **`models[].multimodal`** 为真的模型作为图像，对其他任何模型丢弃，绝不展平为文本；它们仅在用户消息上接受，如 OpenAI 一样，在任何其他角色上以 **`400`** 拒绝，其他部分类型也是如此。客户端可以移交的内容是有界的：最多 128 个工具（**`httpserver.max_client_tools`**）、工具的 **`parameters`** 最多 256 KiB（**`httpserver.max_client_tool_schema_bytes`**）、每条消息 16 张图像和每个图像 URL 字符串 20 MiB（数据 URL 携带图片本身），超过则请求以 **`400`** 拒绝；两个工具界限在 **`POST /v1/responses`** 上也成立，其拒绝携带 **`error.param`** `tools` 和 **`error.code`** `too_many_tools` 或 `tool_parameters_too_large`，其消息命名所提供的内容、限制以及要提升的设置；https 图像地址按原样交给提供商，coddy 绝不获取它。由工具调用组成的 JSON 答案具有 **`content`** `null`，如 OpenAI 渲染的那样。**agent** / **plan** / **ask** 配置文件运行 coddy 自己的工具并拒绝客户端的，且不接受尾随 **`tool`** 消息，尽管最后一条用户消息的图片到达多模态配置文件模型。通过任一端点启动的 **agent** / **plan** / **ask** 轮次以丰富形状发布到输入框中继，无论调用者收到什么，因此观看会话的浏览器无论如何都能看到其工具调用。

### Direct Responses

使用 **`models[].model`** 选择器时，**`POST /v1/responses`** 实现 OpenAI Responses API 的无状态子集。每个请求在 **`input`** 中提供其整个对话，即使有 **`X-Coddy-Session-ID`**。存储的会话历史被替换，而非附加到请求。没有该头则[不存储任何内容](#model配置文件与直接完成)。配置文件 **`agent`**、**`plan`** 和 **`ask`** 保留上述字符串输入、会话历史和 Coddy 事件方言。

**`input`** 接受字符串或类型化项数组。文本消息使用 **`role`** 和字符串内容或文本部分（用户/系统/开发者为 **`input_text`**，助手为 **`output_text`** 或 **`refusal`**）。**`reasoning`** 项的 **`summary`** 接受 **`summary_text`** 部分。重放返回的 **`function_call`** 项及其 **`call_id`**、**`name`** 和 JSON 字符串 **`arguments`**，随后是 **`function_call_output`** 项，具有相同的 **`call_id`** 和字符串或 **`input_text`** 输出。最终输入消息必须是用户消息或函数输出。Coddy 转发提供的函数；调用者执行它们。

可选的 **`instructions`** 为系统消息添加前缀。**`tools`** 使用扁平的 **`{type:"function", name, description, parameters}`** 条目；**`strict: false`** 被接受，**`strict: true`** 不受支持。**`tool_choice`** 接受 **`auto`** 或 **`none`**。**`max_output_tokens`**、**`temperature`**、**`top_p`** 和 **`reasoning.effort`** 使用与直接 Chat Completions 相同的提供商验证。未知字段和不支持的能力返回 **400**，包括 **`previous_response_id`**、**`store: true`**、**`background`**、加密推理、内置工具以及标准 **`input_image`** / **`input_file`** 部分。**`store: false`** 和现有的 **`inline_files`** 扩展仍受支持。直接请求不接受工作区 **`attachments`**。

JSON 答案具有 **`id: "resp_…"`**、**`object: "response"`**、**`created_at`**、**`model`**、**`status`**、类型化 **`output`**、**`error`**、**`incomplete_details`** 和 **`usage`**。输出项包含推理摘要、带有 **`output_text`** 部分的助手消息或函数调用。已知用量包含 **`input_tokens`**、**`output_tokens`** 和 **`total_tokens`**；未知用量为 **`null`**。输出限制或内容过滤器停止产生 **`status: "incomplete"`** 及其原因。

使用 **`stream: true`** 时，SSE 携带递增 **`sequence_number`** 的命名 **`response.*`** 事件。**`response.created`** 和 **`response.in_progress`** 先于输出项/内容部分添加、文本/推理摘要/函数参数增量及其完成事件。终止事件是 **`response.completed`**、**`response.incomplete`** 或 **`response.failed`**。此分支上没有 **`chat.completion.chunk`**、**`coddy_meta`** 或 **`[DONE]`** 帧。流式传输之前的提供商错误使用正常的 HTTP 错误信封；流打开后以 **`response.failed`** 结束。请求的 **`stream`** 独立于 **`models[].stream`** 选择此线格式。

在 Chat Completions 上，助手历史接受 **`reasoning_content`** 及其别名 **`reasoning`** 作为字符串或 null。空/null 值回退到另一个别名；冲突的非空值和非字符串值返回 **400**。助手推理在重放时保留，包括工具调用消息，并作为 **`reasoning_content`** 序列化到 OpenAI 兼容上游。其他角色上的有效推理字段被忽略。JSON 助手答案暴露 **`reasoning_content`**；直接 Responses 改为使用类型化推理摘要项。

### 会话记忆 REST（**`-tags=http,memory`**）

这些 **`/coddy/sessions/{id}/memory/*`** 路由仅在 **`coddy`** 使用 **`memory`**（**`external/httpserver/memory_http.go`**）构建时注册。没有 **`memory`** 的普通 **`http`** 构建返回 **`404`**（**`memory_http_stub.go`**）。

| 方法 | 路径 | 说明 |
|--------|------|-------|
| GET | **`/coddy/sessions/{id}/memory/tree`** | 没有 **`root`** 时，列出 **`global`** 和 **`workspace`**。否则列出允许的 **`.md` / `.txt`** 子项（遍历受保护）。 |
| GET | **`/coddy/sessions/{id}/memory/file`** | 查询 **`root`** + **`path`**。UTF-8 内容。 |
| PUT | **`/coddy/sessions/{id}/memory/file`** | JSON **`{"root","path","content"}`**。 |
| POST | **`/coddy/sessions/{id}/memory/dir`** | 新子目录的 JSON **`{"root","path"}`**。 |

### 调度器 REST（**`-tags=http,scheduler`**）

在普通 **`http`** 构建中和未链接 **scheduler** 时（客户端 **404**），路径**缺失**于 OpenAPI。链接时，响应使用与其他 **`/coddy`** 路由相同的 **`ErrorEnvelope`** JSON。当该进程的 **`scheduler.enable`** 为假时为 **`503`**。处理程序加上合并的调度器 OpenAPI 片段位于 **`external/httpserver/scheduler_http.go`**（**`http`**、**`scheduler`**）；省略 **scheduler** 时 **`scheduler_http_stub.go`** 不注册任何内容。

## **`model`**、配置文件与直接完成

- **`POST /v1/chat/completions`** 和 **`POST /v1/responses`** 要求 **`model`** 恰好是 **`GET /v1/models`** 中的一个 **`id`**（会话操作配置文件 **agent** / **plan** / **ask** 或 **`models[].model`** 条目）。
- **agent** / **plan** / **ask** 选择 Coddy 智能体（ReAct、工具）。可选的 JSON **`metadata.model`**（**`models[].model`** 选择器）更新会话 **`SelectedModelID`**。省略 **`metadata`** 或省略 **`metadata.model`** 以遵循 **`EffectiveModelID`**（会话 **`selectedModelId`** 然后 **`agent.model`**）。**`metadata.model`** 设置为 **`null`**、**`""`** 或未知选择器为 **400**。可选的 **`metadata.settingsVersion`** 是客户端应用的最后设置快照的版本：当服务器此后发布了更新的快照时，请求的 **`metadata.model`**、**`metadata.reasoning`** 和模式被忽略，会话自己的设置成立，因此未看到别处所做更改的标签页无法撤销它。可选的 **`metadata.reasoning`** 设置会话推理级别（在任何 **`metadata.model`** 更改后解析）；它必须是有效模型的 **`reasoning_levels`** 之一（**`null`** / **`""`** 清除它；任何其他不支持的值都是 **400**）。智能体将该级别映射到 OpenAI **`reasoning_effort`**、Anthropic 扩展思考 **`budget_tokens`** 或对于具有自适应思考的 Claude 模型为 Anthropic **`output_config.effort`**；OpenAI 兼容提供商（包括 **`neuraldeep`**）上的 **`qwen3*`** 模型还会发送 **`chat_template_kwargs`** **`{"enable_thinking": true}`**，以便聊天模板思考开关保持开启；**`codex`** 提供商将其作为 Codex **`reasoning.effort`**（**`minimal`** 变为 **`none`**）连同 **`summary: auto`** 和加密推理重放一起发送。
- **`model`** 列出 **`models[].model`** YAML 选择器时每次调用运行**一个直接 LLM 请求**（无 ReAct）；该分支上带有 **`model`** 键的 **`metadata`** 以 **400** 拒绝（仅将 **`model`** 用作路由字段）。
- 没有 **`X-Coddy-Session-ID`** 的直接调用是无状态的：Coddy 不写入任何内容、不列出会话、答案中不命名任何会话。客户端在每次请求时发送其整个对话，因此调用无需存储任何内容。带有该头时调用保留在该会话中，如果该会话尚不存在则创建它：想要稍后读取对话记录或用 **`POST /coddy/sessions/{id}/cancel`** 停止调用的客户端发送自己的 ID。没有该头时，关闭连接会停止调用。**agent** / **plan** / **ask** 轮次总是在会话中运行，并在头缺失时创建一个。
- 由 **`type: acp`** 提供商提供服务的模型（本地 ACP 智能体，[ACP 智能体作为模型](../features/acp-provider.md)）仅通过 **agent** / **plan** / **ask** 配置文件应答：作为 **`POST /v1/chat/completions`** 或 **`POST /v1/responses`** 的直接模型它以 **400** 拒绝（`invalid_request_error`），因为智能体运行自己的工具并保持自己的对话，而非接受调用者的消息和工具。
- 在 **`POST /v1/chat/completions`** 上，直接模型为该一次请求接受请求的生成选项。**`max_tokens`**，或其更新的 OpenAI 名称 **`max_completion_tokens`**（请求仅当它们一致时才能同时携带两者），替换模型的 **`max_tokens`**，**`temperature`** 替换其 **`temperature`**，包括 **`0`**。没有它们时配置值适用，没有请求更改配置或泄漏到另一个请求。提供商无法按要求发送的值在创建会话或联系提供商之前以 **400** 拒绝：低于 1 的上限、超出 0-2 的温度（**`anthropic`** 提供商为 0-1），以及 **`codex`** 模型上的任一选项，因为 Codex 后端拒绝两者。请求的温度也发送在推理级别旁边，此处配置的温度被省略：模型是否接受两者是后端的答案（vLLM 上的 Qwen3 思考接受，OpenAI 的推理模型拒绝）。
- 同一请求上的 **`reasoning_effort`** 选择推理级别，它必须是 **`GET /v1/models`** 为该 ID 列出的 **`reasoning_levels`** 之一；任何其他值，或对不列出任何级别的模型的任何值，为 **400**，绝无静默降级。省略、**`null`** 或 **`""`** 时，模型的 **`reasoning_default`** 适用，没有默认值的模型根本不获得推理级别（默认思考的 Claude 模型仍以自己的默认努力思考）- 与级别 **`none`** 的请求不同，**`codex`** 模型提供并如此接收。该级别作为 OpenAI **`reasoning_effort`**、作为 Anthropic 扩展思考（其中请求的 **`max_tokens`** 在思考预算之上不留空间时为 **400** 而非静默提高）、对于具有自适应思考的 Claude 模型为 Anthropic **`output_config.effort`**（它们不取预算，因此任何正的 **`max_tokens`** 都保留；见 [配置](../getting-started/configuration.md#模型提供商参考)）或作为 Codex **`reasoning.effort`** 传输，JSON 答案将其报告为 **`metadata.reasoning_effort`**。
- **agent** / **plan** / **ask** 配置文件拒绝这些字段：配置文件轮次是一系列 LLM 调用，每个都按配置文件模型的配置值，其推理级别来自 **`metadata.reasoning`**。
- 直接答案仅由提供商自己的终止信号完成：来自 OpenAI 兼容服务器的 **`finish_reason`** 或 **`[DONE]`**、来自 Anthropic 的 **`stop_reason`**、来自 Codex 的 **`response.completed`** 或 **`response.incomplete`**。Codex 的 **`response.incomplete`** 保留迄今所写的文本并报告其原因（**`max_output_tokens`** 为 **`finish_reason`** **`length`**，**`content_filter`** 为 **`content_filter`**；任何其他原因是错误），**`response.failed`** 是携带后端代码和消息的错误。在任何终止信号之前关闭的流，或其事件在其 JSON 内部结束的流，是命名截断的错误（JSON 答案上为 **`500`**，流上为错误帧且没有完成的选择），绝不是 **`stop`**，且文本到达客户端后的失败不会重试为第二个副本。
- 模型提供商以 HTTP 状态应答的失败在到达客户端的途中保持该状态，在直接完成和 **agent** / **plan** / **ask** 轮次上都一样，因此客户端可以区分提供商永远不会接受的请求和中断。提供商 **4xx** 以相同状态应答：超过计划输入限制的请求为 **400**，被拒绝的密钥为 **401**。**429** 在提供商命名暂停时，或在 Coddy 选择不等待用量限制重置时携带 **`Retry-After`**。提供商 **5xx** 变为 **502 Bad Gateway**，当 **503** 命名一个时带有提供商的 **`Retry-After`**，提供商 **504** 或请求超时变为 **504 Gateway Timeout**。错误对象命名提供商的状态：**`{"error":{"message":"...","type":"upstream_error","code":null,"param":null,"upstream_status":400}}`**，流式请求在其错误帧中携带相同的对象。**500** 留给 Coddy 本身的失败，包括在其终止信号之前被切断的流。

Chat Completions 和配置文件 Responses 的非流式回复包括 **`metadata`**，其 **`model`** 设置为有效 YAML 后端选择器（**`api_model`** 可能暴露 REST 模型 ID）。

## 会话与头

### 没有 **`X-Coddy-Session-ID`**

`POST /v1/chat/completions` / **`POST /v1/responses`** 为该流程分配随机会话捆绑包（ACP **`session/new`**）。

### 带有 **`X-Coddy-Session-ID`**

1. 活动的内存中指捆绑包胜出。
2. 否则当 **`session.json`** 存在时从磁盘加载。
3. 否则用提供的标识符固定 **`session/new`**（新的空捆绑包文件夹）。

格式错误的 ID（**HTTP 400**）。专用的 **`/coddy/*`** 辅助函数在持久化不可用时返回 **503**（`Manager` 缺少 **`FileStore`**，主要在测试中）。

### 每会话模型（内置 UI）

- **`GET /coddy/sessions/{id}/messages`** 返回 **`model`**（会话的有效 YAML 后端）、**`selectedModelId`**（**`session.json`** 中存储的覆盖，可能为空）、**`selectedReasoning`**（会话的有效推理级别，模型没有时为空）以及 **`mode`**（会话配置文件 `agent`、`plan` 或 `ask`；远程客户端在加载时恢复它）。
- **`PATCH /coddy/sessions/{id}`** 接受 **`selectedModelId`** 以为该会话设置 YAML **`models[].model`** 选择器（未知 ID 为 **400**）、**`selectedReasoning`** 以设置推理级别（必须是模型的 **`reasoning_levels`** 之一；空清除它；不支持的值 **400**）以及 **`selectedToolset`** 以为会话选择 **`toolsets[]`** 预设，或 **`default`** 为模式的所有工具（未知名称为 **400**；保留在 **`session.json`** 中，[工具集](../getting-started/configuration.md#工具集)）。**`GET /v1/models`** 命名每个模型的工具集（**`toolset`**，没有则为空），并且当配置有预设时，设置快照携带 **`toolset`** 和 **`toolsetChoices`**。
- SPA 在打开聊天时从 **`settings`** 快照恢复 **Model** 和推理级别：会话自己的值，而 **`model`** 和 **`selectedReasoning`** 命名运行中轮次所持有的。更改 **Model** 写入 cookie **`coddy_llm_model`**（下一个 **New chat** 的默认值）并 **`PATCH`** 活动会话。

## 内存根

匹配 `external/memory/README.md`：**`global`** 使用配置的 **`memory.dir`**（回退 **`$CODDY_HOME/memory`**）。**`workspace`** 为该会话捆绑包解析为 **`$CWD/.coddy/memory`**。**`agentMemory`** 占位符保持仅智能体（`session.json`），此处不可 REST 编辑。**`workspace`** 根中的链接绝不会通向其外：会如此的路径为 **400**，当 **`.coddy/memory`** 或 **`.coddy`** 本身是链接时每个路由也是如此（[存储布局](../features/memory.md#存储布局)）；**`global`** 根中的链接被跟随。

当会话在 **`bypass`** 中运行时，交互式工具权限提示被绕过，除了强制的：**`PreToolUse`** 钩子的 **`ask`** 以及决策检查未清除的命令。否则内置 UI 在 **`POST /v1/responses`**（**`stream: true`**）期间显示 **`event: permission`**，并通过 **`POST /coddy/sessions/{id}/permission`** 完成轮次（与 **`question`** 相同的模式）。

## CLI 标志

等同于 **`coddy acp`**：**`--config`**、**`--home`**、**`--cwd`**、**`--sessions-dir`**、**`--session-id`**、**`--log-*`**、可选的 **`--scheduler`** 和 **`--mcp-project-trust ask|allow|deny`**（为本进程覆盖 **`mcp.project_trust`**；见 [mcp-integration.md](../features/mcp.md)）。

网络标志：**`-H` / `--host`**、**`-P` / `--port`**，回退到 YAML **`httpserver.host` / `httpserver.port`**，再回退到 **`127.0.0.1:12345`**。绑定默认为回环，因为现在一个进程启动每个启用的子系统：要求 Telegram 机器人的操作员绝不能作为副作用在每个接口上发现智能体 API。传递 **`-H 0.0.0.0`**（或设置 **`httpserver.host`**）以接受来自其他机器的连接，如果你在没有令牌的情况下这样做，请预期"无需身份验证即可到达"的警告。

身份验证：**`--auth-token <token>`**（也是 **`CODDY_HTTP_TOKEN`**）启用持有者身份验证而不将机密写入 **`config.yaml`**。

子系统开关：**`--http=false`** 在没有 API 的情况下运行其他一切，**`--gateway`**、**`--swarm`** 和 **`--scheduler`** 为一次运行覆盖其 **`enable`** 键，中继自己的设置为 **`--swarm-host`**、**`--swarm-port`**、**`--swarm-auth-token`**、**`--swarm-pairing-token`** 和 **`--swarm-allow-insecure`**。

## 会话工作区预览

这些路由使用 **`{id}`** 的工作区，需要时从持久化加载。
它们绝不从查询或会话头选择根。路径为工作区相对路径，
每个文件系统操作都由 `os.Root` 限制；raw/text 仅接受常规
文件。逃逸的符号链接或特殊文件不可用。

| 方法 | 路由 | 契约 |
|---|---|---|
| GET | `/coddy/sessions/{id}/workspace/tree` | 一个目录级别：文件夹优先，然后是文件，每组按名称排序。根的 `path_rel` 为空。`limit` 默认为 200 且上限为 1000；将 `next_cursor` 按原样传回为 `cursor`（不透明位置；格式错误的为 `400`）。返回 `entries`（`name`、`path_rel`、`kind`、`size_bytes`、`mod_time`）、`next_cursor` 和 `has_more`。种类为 `file`、`directory`、`symlink` 和 `special`；目录大小为零。行不包含 MIME 嗅探。`include_hidden=1` 显示隐藏名称、`node_modules` 和 `vendor`；过滤仅用于导航。 |
| GET / HEAD | `/coddy/sessions/{id}/workspace/raw` | `path_rel` 要求常规文件。固定的扩展名加嗅探允许列表允许内联光栅图像、音频、视频、PDF 和 `.txt`；HTML、SVG 和未知类型始终使用附件和 `application/octet-stream`。`download=1` 强制附件。支持 Range（206/416）、弱元数据 ETag 和条件 304。设置 `private, no-cache`、`nosniff`、`no-referrer` 和沙箱 CSP。 |
| GET | `/coddy/sessions/{id}/workspace/text` | 从有界编码样本流式解码，包括旧版文本。`offset` 基于零（默认 0，最大 10000000），`max_lines` 默认为 300 且上限为 1000。返回无终止符的 `lines`、`offset`、`next_offset`、`has_more`、`total_lines_known`（到达 EOF）、`charset`、`etag`、`mod_time` 和 `size_bytes`。文件大小不限制在 512 KiB；每行和每页限制为 1 MiB。`etag` 将后面的页面固定到其版本；不匹配或并发替换为 409。无法解码的输入为 415，过大的行为 413。 |
| POST | `/coddy/sessions/{id}/workspace/media-token` | 需要正常的 API 身份验证。正文：`{"path_rel":"clip.mp4","download":false}`。返回 `token` 和 `expires_at`，带有 `Cache-Control: no-store`。将令牌作为 `access_token` 添加到具有相同路径和下载模式的原始请求。 |
| POST | `/coddy/sessions/{id}/workspace/stat` | 告知哪些工作区相对路径存在，以及作为什么。正文：`{"paths":["internal/foo.go","docs"]}`，最多 256 个路径。返回 `object`（`coddy.workspace_stat`）和 `entries`，每个存在的路径一个 `{"path_rel","kind"}`，`path_rel` 按询问的原样和 `kind` 为 `file`、`directory`、`symlink`（绝不跟随）和 `special` 之一。格式错误、绝对、离开工作区或不命名任何内容的路径被排除在 `entries` 之外而非使请求失败，询问两次的路径仅报告一次。`Cache-Control: no-store`。Web UI 询问它答案命名的哪些路径是它可以打开的文件。 |

媒体能力**仅**在原始路由上替代持有者/cookie 身份验证，包括 HEAD 和后续范围。其版本化 HMAC 绑定会话、工作区、路径、查看/下载模式和最多一小时的到期时间。被更改、过期或不匹配的能力返回 401，即使伴随持有者头。树、文本和令牌铸造仍使用正常的身份验证门。

签名密钥与配置的 API 凭据（`httpserver.auth_token`、CLI/环境令牌）域分离，或在未配置持有者凭据时为密码登录哈希。因此匹配的副本和重启保留 URL；轮换该凭据会使未完成的 URL 失效。未经身份验证的服务器使用每进程随机密钥。API 凭据绝不放置在媒体 URL 中。CORS 允许 HEAD、Range 和 If-None-Match 并暴露 Content-Range、Accept-Ranges、ETag 和 Content-Disposition。

## Canvas

聊天[画布](../features/canvas.md)的路由：会话工作区的 `.canvas` 文件
（JSON Canvas 1.0，Obsidian 画布的格式），其命名 HTML 页面的文件节点作为实时
框架运行。子智能体的 ID 作用于其生成树的顶级会话的画布。每个路由用 `file` 查询命名其
文件，相对于工作区，即点命名文件夹之外的 `.canvas` 文件
（否则为 `400`）；`GET .../canvas` 和 `POST .../canvas/frames` 不取任何内容并作用于聊天的
当前画布：页面最后显示或打开的文件。当 `tools.canvas.enable` 为假时每个路由都回答 `404`，对于未保存的会话为 `409`。

| 方法 | 路由 | 契约 |
|---|---|---|
| GET | `/coddy/sessions/{id}/canvas` | 画布作为板：`session_id`、`file`、`current`（它是否是聊天的当前画布）、`revision`、`stamp`（文件变化时移动，无论谁更改的；消失时为 `missing`）、`error`（为何无法读取；此时不显示其任何内容）、`frames[]`、`items[]`、`edges[]`。框架携带 `id`（其节点的）、`path`、`root`、`title`、`device`、`width`、`height`、`x`、`y`、`added_by`、`gen`、`stamp`（其根下文件的名称、大小和时间的摘要，它们变化时移动）、`url`（其相对于 API 基础的地址，现已签名）及 `expires_at`，以及 `report`，最新浏览器报告的计数。`items[]` 是其其他节点（`id`、`type` - `text`、`file`、`link` 或 `group` - `x`、`y`、`width`、`height`、`color`、`text`、`file`、`url`、`label` 以及对于不运行的页面为 `note`）、`edges[]` 其行（`id`、`fromNode`、`fromSide`、`fromEnd`、`toNode`、`toSide`、`toEnd`、`color`、`label`），每次请求时从文件读取。没有 `file` 时为当前画布，或当聊天没有画布时以空的 `file` 回答。读取不写入任何内容。`Cache-Control: no-store`。 |
| POST | `/coddy/sessions/{id}/canvas/open` | 使 `file` 成为聊天的当前画布，即未指定文件显示的页面所继续的那个；Web UI 在用户打开文件时调用它。不向文件写入任何内容；对于缺失或无法解析的文件为 `400`。回答板。 |
| POST | `/coddy/sessions/{id}/canvas/frames` | 将页面放到画布上：`{"path","root","title","device","width","height"}`，页面相对于工作区，作为 `file` 的文件节点，或当前画布的，或在新 `canvas/<page folder>.canvas` 中（名称被采用时编号）而聊天没有画布。相同大小的相同页面是一个框架（`reason: shown`）；超过 24 个框架为 `409`。回答 `reason`、`file`、`created`（文件为它而制作）、`frame`、`revision`。 |
| DELETE | `/coddy/sessions/{id}/canvas/frames/{frame}` | 将框架从画布上取下：其节点及其边缘离开文件，页面的文件保留，框架的每个地址停止工作。 |
| POST | `/coddy/sessions/{id}/canvas/frames/{frame}/rotate` | 将框架移动到其下一代，因此此前分发的每个地址停止工作；Web UI 在页面离开画布导航时调用它。回答框架及其新地址。文件不写入。 |
| POST | `/coddy/sessions/{id}/canvas/frames/{frame}/report` | 浏览器所看到的：`stamp`（它加载的文件）、`loaded`、`closed`、`error`、`title`、`console[]`（`level` `error` 或 `warning`、`message`、`source`、`line`、`column`）。保存在内存中，每个文件的每个框架最新的，最多 1,000 个字符的 20 行；`canvas_inspect` 读取它。`204`。 |
| PATCH | `/coddy/sessions/{id}/canvas/nodes` | 在一次更改中移动或调整节点大小：`{"nodes":[{"id","x","y","width","height","device"}]}`，框架（按大小或 `device`）以及卡片、链接和组，最多 500 个，一次写入文件。全部或没有：文件不持有的 ID 为 `404`。 |
| GET / HEAD | `/coddy/canvas/{capability}/{path}` | 框架的文件，`path` 相对于其根；`.coddy/bridge.js` 是桥接脚本。 |

写入保留它们不更改的每个节点、边和键，包括 Coddy 不知道的键及其顺序，并像 Obsidian 1.14 那样逐字节写入文件：一个纯值节点一行，一个持有对象的节点每行一个键，Coddy 更改的节点按 Obsidian 的键顺序，字符按 `JSON.stringify` 转义它们的方式转义，文件在它结束的地方结束。框架的设备和标题放在其节点的 `coddy` 键下；Coddy 未移动的节点保留自己的数字。比页面文件夹更宽的根、框架地址背后的代次和当前画布保存在会话捆绑包（`canvas.json`）中，绝不在文件中，因此文件无法扩大其页面读取的内容。一个文件的读取-修改-写入跨聊天是一轮次，自读取以来在文件中删除的节点保持删除。

通过画布所做的每次更改都在 `GET /coddy/events` 上作为 `event: canvas_changed` 通告
带有 `{"object":"coddy.canvas_changed","sessionId","file","revision","frameId","reason","at"}`；
`reason` 为 `added`、`shown`、`updated`、`removed` 或 `opened`。

**框架的地址。** `/coddy/canvas/<capability>/<page>` 仅由其
路径中的能力进行身份验证：无持有者、无 cookie，因此它在任何来源的 iframe 中加载，通过远程服务器
和通过集群中继都一样。能力是对会话、`.canvas` 文件、
框架、其工作区、其根、其代次和 12 小时到期时间的 HMAC，用从媒体令牌背后的机密为
画布派生的密钥签名，因此媒体令牌绝不会通过为框架地址。当文件在该代次以该根在会话的工作
目录中持有框架时它有效；被移除、重新指向或轮换的框架，以及移动到另一个文件夹的会话，回答
`401`。文件通过 `os.Root` 提供，途中没有符号链接
且打开的文件检查为所走的那个：仅 `GET` 和 `HEAD`，没有
点命名路径，文件夹的 `index.html`（带有 `301` 以添加缺失的斜杠），绝无列表。

路由的每个答案都携带：

- `Content-Security-Policy: sandbox allow-scripts allow-forms allow-modals; default-src 'self' data: blob: 'unsafe-inline' 'unsafe-eval' <sources>; connect-src 'self' <sources>; form-action 'none'; base-uri 'self'; frame-ancestors *`，来源为 `tools.canvas.allow_cdn` 和 `tools.canvas.allowed_sources` 的 CDN；
- `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`Cache-Control: no-store`；
- `Access-Control-Allow-Origin: *`，因为页面自己的模块脚本和获取来自不透明来源；路由的预检 `OPTIONS` 以相同方式应答。

HTML 页面在其头部开头获得桥接脚本和 `<meta name="referrer" content="no-referrer">`。页面最多 10 MB：`canvas_show` 和 `POST .../canvas/frames` 拒绝更大的
页面，增长超过它的页面以 `413` 和一个简短的页面（带有桥接）回答，说明如此。

**不透明来源。** 其他每个路由都拒绝其 `Origin` 头为 `null` 的请求，以 `403`，
在身份验证之前且无论它携带什么凭据：沙箱页面发送 `Origin: null`，而
它从文件读取的持有者或中继替换的凭据都不能让它驱动
服务器。自己发送 `Origin: null` 的客户端（`file://` 页面）以相同方式拒绝；不
发送 `Origin` 的客户端不受影响。
