# 画布

画布是工作区中的一个 `.canvas` 文件，采用 JSON Canvas 格式，即 Obsidian 画布的格式，它在 Web 界面的文件窗口中像任何其他文件一样打开。它的标签页显示一块板：文件中指定的 HTML 页面作为实时框架在其中运行，它的卡片、分组和连线按 Obsidian 的绘制方式呈现。你逐个点击浏览页面，指向某个元素，在板下方的提示词栏中说明要改什么，智能体就会读取浏览器所看到的内容。因为板就是文件，所以它在 git 中；在 Obsidian 中绘制的板可以在 Coddy 中打开，在 Coddy 中制作的板也可以在 Obsidian 中打开。

用你自己的话提问：

```text
Sketch a landing page for the shop and put it on the canvas, phone and desktop.
```

智能体用文件工具在它自己的文件夹中编写页面，并调用 `canvas_show`。若聊天中还没有画布，它就创建一个 `canvas/<folder of the page>.canvas`，文件窗口会在新框架处打开它；在手机上聊天界面保持不变，工具卡片会打开该文件。

![文件窗口中的一个 .canvas 文件：同一页面的两个框架，分别为桌面尺寸和手机尺寸，板下方是提示词栏](../../assets/canvas/canvas-board-dark-1280.png)

*同一个页面的两种尺寸：每个框架运行的都是该页面自己的文件。*

## 把页面放到画布上

框架是会话工作区中的一个 HTML 页面（`.html` 或 `.htm`，位于以点开头的文件夹之外，最大 10 MB；超过此大小的内联数据应放到其所在文件夹的文件中），同时也是 `.canvas` 文件中的一个文件节点。有两种方式把它放上去：

- 智能体以该页面的路径调用 `canvas_show`，并用 `file` 指定画布；
- 在文件窗口的 **更多** 菜单中为某个 HTML 文件选择 **在画布中打开**。

未指定文件而显示的页面会放到该聊天自己的画布上：即某个页面最近一次被显示所在的 `.canvas` 文件，或你在文件窗口中最后打开的那个文件。若聊天还没有画布，就会新建一个 `canvas/<folder>.canvas`，名称被占用时加上编号。对话记录中的 canvas_show 卡片会在其放置该框架的位置打开文件。

| 尺寸 | 宽度 × 高度 |
|---|---|
| `desktop`（默认） | 1280 × 800 |
| `tablet` | 820 × 1180 |
| `phone` | 390 × 844 |
| 自定义 | 320-3840 × 320-4320，需同时满足 `width` 和 `height` |

同一个页面在相同尺寸下就是一个框架：再次显示它会聚焦到该框架。以另一种尺寸显示会新增第二个框架，一个页面就是这样同时在三种宽度下检查的。一个画布最多运行 24 个页面；超出的节点会被绘制为卡片。画布的地址就是文件窗口的地址，`#/s/<session>/files?path=<file>.canvas`。

框架加载其**根**下的文件，默认是页面所在的文件夹。位于工作区顶层文件夹中的页面以整个工作区为根，可以读取其中以点开头的文件夹之外的每个文件，因此工具会对此发出警告：请把页面放在它自己的文件夹中。

## 在板上操作

板左上角的开关决定点击的作用：

- **交互** - 在页面上的点击、按键和滚轮都交给页面处理；
- **评论** - 点击页面上的某个元素即将其选中。

在板上滚动滚轮会以指针位置为中心缩放，方式与图片查看器和集群地图的缩放相同：同样长度的一格滚动会让指针下的内容放大或缩小一倍。拖动空白板会平移，两指可捏合缩放。板右上角的缩放控件与它们相同：减号、当前级别（百分比，或在板处于适配状态时显示适配图标；点击一下即适配全部）、加号；板获得焦点时，`+`、`-` 和 `0` 效果相同。平移或缩放会把整块板作为一个图层移动，不会重新绘制任何内容，因此页面很多的板与空板一样流畅。框架的标题栏可以移动它，它的按钮可以改变尺寸、重新加载以及把它从画布上移除（文件保留）。

选中的元素会在旁边打开一个注释。**添加** 会把它变成板下方提示词栏中的一个标签，**发送** 会把标签和文本作为该聊天的一条提示词发出：每个元素都带上它所在的页面、尺寸、CSS 选择器、文本和注释。当某个轮次正在运行时，消息会在[消息队列](message-queue.md)中等待。轮次等待的权限请求或问题会显示在栏上方，因为窗口遮住了聊天。**聊天** 会关闭文件窗口并回到对话；该栏会按文件保留写了一半的请求，直到页面生命周期结束。

![评论模式：选中了页面的一个标题，并附有给智能体的注释](../../assets/canvas/canvas-comment-dark-1280.png)

*选中的元素及其注释：添加后即成为提示词栏中的一个标签。*

当框架根下的某个文件发生变化时，该框架会重新加载，且只有它：每次工具调用之后、服务器通告的每次变更时，以及打开期间每 4 秒，板都会被重新读取；其文件发生变动的框架会重新加载，而没有产生变化的读取不会绘制任何内容。Escape 键先关闭注释，再退出评论模式，然后关闭窗口。窗口 **更多** 菜单中的 **预览** 会在文件的 JSON 与画面之间切换该标签页。

在手机上，文件窗口占据顶部栏以下的屏幕，板取代文件的位置，框架初始即为适配状态。

![手机上的一个 .canvas 文件：框架已适配，选中的元素成为提示词栏中的一个标签](../../assets/canvas/canvas-board-dark-390.png)

*在手机上：同一块板，适配到屏幕。*

## 智能体看到什么

显示框架的浏览器会就它作出报告：是否加载成功、标题、控制台的错误和警告，以及无人捕获的异常。`canvas_inspect` 读取这些报告，因此智能体无需让你打开控制台就能找到出错的脚本。编辑之后它传入 `wait_seconds`，得到针对新文件的报告，或者得知没有报告返回。控制台的行是页面自身的输出，会作为不可信数据交给模型，绝不会当作指令。只有在有人打开该画布时才有报告；报告保存在内存中，每个框架 20 行。

| 工具 | 参数 | 作用 |
|---|---|---|
| `canvas_show` | `path`、`file`、`title`、`device`、`width`、`height`、`root`、`frame` | 把页面放到 `.canvas` 文件 `file` 上（缺失时创建），或放到聊天的画布上，或让框架 `frame` 指向它；把 `.canvas` 文件作为 `path` 时，使该文件成为聊天的画布 |
| `canvas_inspect` | `file`、`frame`、`wait_seconds` | 读取一个框架或所有框架的浏览器报告，针对当前文件最多等待 15 秒 |

在聊天所在文件夹中工作的子智能体会把它的页面显示在聊天的画布上，因此来自三个子智能体的同一页面的三个变体可以并排比较。位于自己的 [worktree](worktrees.md) 中的子智能体会被拒绝：它的页面不是聊天画布所在文件夹中的文件。

## Obsidian 画布

Obsidian 把画布保存为一个 [JSON Canvas 1.0](https://jsoncanvas.org) 格式的 `.canvas` 文件：四种节点（文本、文件、链接和分组）放置在一个平面上，节点之间用连线连接。Coddy 的每个画布都是这样的文件，因此工作区中的 `.canvas` 文件会在文件窗口中作为它的板打开，打开它就会使它成为该聊天的画布：智能体接下来显示的页面都会放到它上面。

![文件窗口中的一个 Obsidian 画布：一个分组，内含一张文本卡片、一则笔记和一个链接，一条带标签的连线通入商店页面的实时框架](../../assets/canvas/canvas-obsidian-dark-1280.png)

*在 Obsidian 中绘制的板：其中的页面作为框架运行，其卡片、分组和连线按原样绘制。*

板会显示文件的以下内容：

- 指定工作区中某个 HTML 页面的文件节点是一个实时框架，尺寸取该节点的大小；
- 文本卡片是它的 Markdown，按 Obsidian 的方式渲染，其中单个换行就是一个换行；
- `.md` 笔记的文件节点会显示该笔记，渲染方式相同，并在板打开期间每 10 秒重新读取一次；图片会显示图片；其他任何文件都是带 **在文件中打开** 的卡片；
- 链接节点是一个卡片，会在新标签页中打开该地址（仅限 `http` 或 `https`）；
- 分组是节点下方的一个框架，带有它的标签；
- 连线是从一侧到另一侧的曲线，带有箭头、标签和颜色；颜色是 JSON Canvas 的六种预设或一个十六进制值。

画布会写回文件的内容：

- 被显示、移动、调整大小或从画布上移除的框架；新框架会成为板上所有内容右侧的一个文件节点，被移除的框架会带走它的连线；
- 在板上拖动的卡片、链接或分组；分组会带走其中的节点；
- 除此之外没有别的。其他每个节点、连线和键都保持原样，包括 Coddy 不认识的键，文件会按 Obsidian 写入的方式逐字节写出：纯值的节点或连线写成一行，含有对象的节点（`styleAttributes`、`coddy` 键）一个键一行，Coddy 修改过的节点的键按 Obsidian 修改节点时给出的顺序排列，字符按 Obsidian 的方式转义，文件在其闭合花括号处结束。在 Obsidian 1.14.4 中保存后，这样的文件只会在那里所做编辑的行上发生变化，而 Coddy 在其于 Obsidian 中打开时写入它，只会改变 Coddy 移动过的行：Obsidian 会读取该改动并在下次保存时保留它。打开或读取文件不会写入任何内容。

Obsidian 在绘制画布时会做自己的修改：图片节点会采用图片的比例，没有指定边的连线会得到它绘制时所用的边。这些改动会在 Obsidian 下次保存后出现在文件中，而不是在 Coddy 保存后。

`canvas_show` 写入该文件时不需要权限提示：只写它所显示框架的节点，不写其他内容；或者在 `canvas/` 下新建一个只含该节点的文件。

JSON Canvas 没有对应字段的框架设置（尺寸无法说明的设备、标题）放在其节点的 `coddy` 键下，Obsidian 会保留它。Coddy 没有移动过的节点保留它自己的数值，即使它小于框架所允许的尺寸。比页面文件夹更宽的根、框架地址背后的代际，以及哪个文件是聊天的画布，都随会话保存，从不写入文件，因此随代码检出而来的 `.canvas` 文件无法扩大其页面可读取的范围：除非 `canvas_show` 在此聊天中扩大了范围，页面只读取它自己的文件夹。打开同一文件的两个聊天会轮流写入它，且各自只写入自己改动的内容。

每当文件被读取时，板都会重新读取它，因此在 Obsidian 中的编辑，或智能体用文件工具所做的编辑，会在几秒内显示在打开的板上。文本卡片、连线和新的链接就是这样在文件中编辑的：画布移动节点，但不写入文本。

节点中的路径相对于工作区，因此工作区就是 Obsidian 的仓库，或者说文件从仓库根目录来命名它的页面。该文件必须是工作区中位于以点开头的文件夹之外的常规文件，最大 8 MB；无法解析的文件会在板上说明这一点，并且永远不会被写入。id 不是字母、数字、`-` 和 `_`（最多 64 个字符）的节点会被绘制为卡片，并且不会运行。

## 页面能做什么

框架在一个不赋予它自身源的沙箱中运行：

- 框架的地址携带它自己的能力：`/coddy/canvas/<capability>/<page>`，由服务器为该会话签名，涵盖 `.canvas` 文件、框架、根和代际，在文件于会话工作目录中以该代际持有该框架期间有效，最长 12 小时；
- 服务器以 `Content-Security-Policy: sandbox allow-scripts allow-forms allow-modals` 响应它，iframe 拥有相同的沙箱，因此页面在不透明源中运行脚本：没有 cookie，没有 Web 界面的存储，也无法访问其 API；`localStorage` 和 `sessionStorage` 在框架生命周期内于内存中工作，表单不会提交到任何地方；
- 每个 API 路由都会拒绝 `Origin` 为 `null` 的请求并返回 403，无论它携带什么凭据，因此页面无法驱动服务器，即使服务器没有令牌；框架自己的文件路由是唯一的例外；
- 页面可以从它自己的地址、`data:` 和 `blob:` 地址加载，在 `tools.canvas.allow_cdn` 开启时从常见 CDN 加载，并从 `tools.canvas.allowed_sources` 的主机加载；`fetch` 和 WebSocket 只能到达它自己的地址和相同的主机；
- 页面可以读取其根下的每个文件并将其发送给上述任何来源：它能读取的就是你放在其根下的内容；
- 导航离开画布的页面会在其框架上说明这一点，框架的旧地址随之失效；**返回页面** 会在新地址下重新加载它；
- 框架不提供符号链接，也不提供以点开头的路径，文件夹只返回其 `index.html`，从不返回列表。

框架的地址通过[远程服务器](../surfaces/console.md#远程模式---remote)和[集群中继](../operate/swarm.md)时与本地一样工作：中继会不带中继自身的凭据将它转发到节点，节点检查的只有路径中的能力。

## 配置

```yaml
tools:
  canvas:
    enable: true          # false hides the tools and the canvas
    allow_cdn: true       # cdn.jsdelivr.net, unpkg.com, cdnjs.cloudflare.com, cdn.tailwindcss.com, Google Fonts
    allowed_sources: []   # more hosts a frame may load from and connect to, as https://host or https://*.host
```

`allowed_sources` 中的 CDN 和主机是页面可以发送其读取内容的去处。这些字段列在[配置参考](../reference/config.md)中。画布和框架的路由在 [HTTP API 参考](../reference/http-api.md#canvas)中。

画布是 Web 界面的一个界面。在控制台中以及通过 ACP 的编辑器中，这些工具同样可用，`.canvas` 文件也会被写入，但没有任何东西运行框架；在那里，[预览服务器](preview-server.md)为你的浏览器提供一个页面。
