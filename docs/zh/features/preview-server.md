# 预览服务器

`preview_server` 工具会将项目中的一个目录作为静态网站提供在空闲的 localhost 端口上，并返回该地址。它存在的意义，正是在你想亲自试用成果的那一刻：从磁盘以 `file://` 打开的页面无法导入 ES 模块、无法 `fetch` 自身的数据，也无法启动 worker，因此 HTML、JS 和 CSS 相关的工作需要先有 Web 服务器，浏览器才能运行它。

用自己的话向它提出请求：

```text
Run this on a web server, I want to click around myself.
```

智能体启动服务器，用链接作答，即 `http://127.0.0.1:53817/`，并邀请你打开它。为此无需安装任何东西：服务器是 Coddy 的一部分，是运行进程内的几个 goroutine，而不是智能体必须在机器上找到的 `python -m http.server` 或 `npx serve`。自带开发服务器的项目（`npm run dev`、`vite`）仍会使用它自己的开发服务器，作为[后台命令](background-tasks.md)。

## 提供的内容

| 参数 | 含义 |
|---|---|
| `path` | 要提供服务的目录，相对于会话的工作目录。省略时，提供工作目录本身。也可以接受文件：将提供其所在目录，返回的地址会打开该文件。 |
| `timeout_seconds` | 经过这么多秒后自行停止服务器。省略时（通常情况），服务器会一直运行，直到被停止。 |

- 端口始终是系统挑选的空闲端口，因此两个会话，或同一会话的两个目录，绝不会冲突。
- 每次请求都会从磁盘读取文件，并以 `Cache-Control: no-store` 响应：保存文件、刷新页面，即可看到修改。
- 带有 `index.html` 的目录会打开该文件；没有该文件的目录则返回目录列表。
- 无论主机的注册表怎么说，`.js` 和 `.mjs` 始终以 `text/javascript`、`.css`、`.json`、`.svg`、`.wasm` 以及具有各自类型的字体发出。浏览器会拒绝以 `text/plain` 提供的 ES 模块，而 Windows 常把 `.js` 当成这种类型。
- 再次请求一个已在提供服务的目录时，会返回当前正在使用的地址，而不是再开第二个端口。

## 运行中任务中的一项任务

该服务器是会话的一个[后台任务](background-tasks.md)，类型为 `server`：

- 它出现在 Web 界面任务面板的运行中任务里，带有 `server` 标签，卡片上直接显示其地址（一个在新标签页中打开的链接，无需先展开任何内容），并带有 "Stop" 按钮；控制台中的 `/tasks` 会显示同一行；
- `background_list` 会向智能体显示它及其地址，`background_output` 返回其请求日志（每个请求一行，`GET /app.js 404`，这通常就是 "页面是空白的" 的全部答案），而 `background_stop` 会结束它；
- 它像任何其他任务一样计入 `tools.background.max_concurrent`。

![运行中的预览服务器所在的任务面板：服务器标签、作为链接的地址、"Stop"，以及已打开卡片的请求日志](../../assets/preview-server-task-dark-1280.png)

*运行中任务里的服务器：其地址是一个链接，而打开的卡片就是它的请求日志。*

与命令不同，它本身没有硬性超时：`tools.background.max_timeout_seconds` 约束的是失控的命令，而不是你要求保持打开的页面。服务器会在以下情况结束：

- 它被停止，无论是被你停止还是被智能体停止；
- 会话被删除，或 Coddy 退出；
- 启动它的调用所设置的 `timeout_seconds` 到期（此时任务会显示为 `timed_out`）。

服务器不会在 Coddy 重启后继续存在：记录会以 `orphaned` 留在会话包中，智能体在被要求时会启动一个新服务器，而过期的行会从任务面板中清除（此时停止操作已没有可终止的对象）。

## 它不会做什么

该工具运行时无需权限提示，因此其范围被刻意限制得很窄：

- **仅限项目。** 目录必须是会话的工作目录或其内部目录（解析符号链接后）；其他任何位置都会被拒绝。文件通过 `os.Root` 打开，因此目录内的符号链接也无法指向其外部。
- **不允许点文件。** 只要路径中有以点开头的元素（`.git`、`.env`、`.coddy`），就会返回 404。目录列表也不会显示它们，目录内的符号链接不能指向这类文件，也不能选择以点命名的路径作为要提供服务的目录。
- **只读。** 仅支持 `GET` 和 `HEAD`；其他方法都返回 405。
- **默认回环。** 服务器绑定到 `127.0.0.1`。在回环绑定下，如果请求的 `Host` 头不是 `localhost`、`127.0.0.1`、`[::1]` 或配置的 `public_host`，就会被拒绝，因此其他位置的网页无法通过将自己的域名指向你的机器来访问你的文件（DNS 重绑定）。不会发送 CORS 头。
- **没有密码保护。** 服务器运行期间，任何能访问该地址的对象都可以读取所提供服务的文件（`Host` 检查只是阻止其他网页访问，并不是身份验证）。在共享机器上，这意味着每个本地进程；在非回环绑定上，则意味着所有能访问该地址的人。

该工具在 `agent` 模式下提供。

## 配置

```yaml
tools:
  preview_server:
    enable: true          # false hides the tool
    host: 127.0.0.1       # bind address, without a port
    public_host: ""       # host written into the address the agent hands out
```

`tools.background.enable: false` 也会关闭该工具：没有任务池，就没有可用于列出或停止服务器的东西。

当 Coddy 运行在浏览器不在的地方（容器、远程机器）时，回环地址无法访问。请绑定到 `host: 0.0.0.0`，并将 `public_host` 设置为你访问该机器时使用的名称；在容器内，端口是随机分配的，因此请发布一个端口范围或使用主机网络。非回环绑定会向所有能访问该地址的对象暴露所提供服务的目录，并且 `Host` 检查不再适用：请有意设置它。这些字段列在[配置参考](../reference/config.md)中。
