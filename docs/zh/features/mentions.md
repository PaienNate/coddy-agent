# 提及

提示词中的 `@` 会让智能体指向某个对象：一个文件、一个行范围、一个文件夹、另一个会话、一条规则、一个子智能体或一个网页。每个界面都读取同一套语法：控制台、Web 界面、通过 ACP 接入的编辑器、Telegram 机器人；服务器会在**消息发送时一次性**解析每个提及，将其变成随同该消息一起传递的附件。模型会将附件与命名它的文本一起读取，后续轮次会严格按照消息发送时的原样重放。

## 提示词可以提及什么

| 写法 | 示例 | 模型收到什么 |
| --- | --- | --- |
| 工作区内的路径 | `@src/app.go` | 文件的文本 |
| 绝对路径、主目录下的路径、工作区之上的路径 | `@/etc/hosts`、`@~/notes.md`、`@../api/schema.sql` | 文件的文本，并以绝对路径标注 |
| 带引号的路径，用于含空格的名字 | `@"notes/my draft.md"` | 文件的文本 |
| 行范围 | `@Dockerfile:21-31`、`@f.go#L21-31`、`@f.go#L21`、`@f.go#21-31` | 仅这些行，并标记为 `lines="21-31"` |
| 文件夹 | `@src/`，或当它是文件夹时的 `@src` | 文件夹的列表 |
| 另一个会话 | `@session:sess_3e23…`（一个 id 或其唯一前缀） | 该会话的摘要 |
| 规则 | `@rule:deploy`，或仅提及规则用 `@deploy`；`.coddy/rules/frontend/style.mdc` 用 `@rule:frontend/style`，`db/.coddy/rules/` 的规则用 `@rule:db/deploy` | 规则正文 |
| 子智能体 | `@agent:explore` | 一条指示：用 `spawn_agent` 将工作交给该子智能体 |
| Coddy 文档中的页面 | `@coddy:features/mentions`、`@coddy:surfaces/gateway#proxy` | 该页面，或该页面中的那一节（[内置文档](built-in-docs.md)） |
| 已保存的设计计划 | `@plans/auth-refactor.plan.md` | 在询问模式下是计划文档；在智能体模式下会运行该计划（[模式](modes.md)） |
| 网页 | `@https://go.dev/doc/effective_go` | 以 Markdown 形式提供页面（JSON 会美化输出，纯文本保持原样） |

提及从 `@` 开始，该字符位于行首，或跟在空白、左括号、引号之后，因此 `user@example.com` 不算提及。在围栏代码块、行内代码段（`` `@Override` ``）或引用行（`> ...`）内，`@` 只是普通文本。

磁盘上不指向任何内容的 `@` 也不是提及：`npm install @google/genai` 指向一个包，除非工作区中存在 `google/genai`，否则不会附加任何内容，Web 输入框也不会高亮它。

在普通文本中输入的提及在哪里结束并不总是显而易见：`@README.md.` 可能是一个名为 `README.md.` 的文件，也可能是句末的 `README.md`，而 `@notes draft.md` 可能是含空格的名字，也可能是文件后面跟着一个词。语法会列出所有可能的读法，最长的优先，磁盘上实际存在的那个胜出。不指向任何内容的提及，例如聊天中的 `@username` 或不存在的路径，仍作为普通文本，不附加任何内容。

Windows 路径（`@C:\Users\me\x.txt`）和带作用域的包文件夹（`@node_modules/@types/node/index.d.ts`）会按路径读取。语法位于 `internal/mention/grammar.go`；Web 输入框用它的一个对应实现来高亮（`external/ui/src/ui/skills/draftAt.ts`），两者都受同一组用例约束（`internal/mention/testdata/grammar_cases.json`）。

## 模型收到什么

每个解析后的提及都会成为消息文本之后的 `<coddy_attachment>` 元素，正文放在 CDATA 中：

```xml
look at @src/app.go:3-5 and @session:sess_3e23

<coddy_attachment path="src/app.go" name="app.go" lines="3-5">
<![CDATA[func main() {
    println("hi")
}]]>
</coddy_attachment>

<coddy_attachment path="session:sess_3e23" name="Refactor auth" kind="session">
<![CDATA[Session sess_3e23 - "Refactor auth"
Workspace: /home/me/project
...]]>
</coddy_attachment>
```

当附件不是文件时，`kind` 指明它是什么（`directory`、`session`、`rule`、`agent`、`plan`、`skill`、`url`、`doc`，以及 `stdin`，用于在输入提示词下的一次性运行中被管道传入的内容，没有任何提及代表它：对话记录会在其位置显示 `[stdin]`，并且其中的任何内容都不会被解析为提及，见[控制台](../surfaces/console.md#提示词下管道输入的数据)）。`mention` 是提及输入时的样子，当它与 `path` 不同时如此，例如 `~/notes.md` 对应 `/home/me/notes.md`；对话记录会把附件折叠回它：Web 界面、重新打开该会话的控制台以及加载该会话的编辑器，都会在消息输入的位置显示 `@~/notes.md`，而绝不会显示文件正文。

每种提及携带的内容：

- **文件**会以内联方式提供，最大 512 KiB，并按编码解码（Windows-1251 和其他旧字符集会转为 UTF-8）。没有行范围的更大文件会作为一条说明附加，说明其大小，并要求模型用 `read` 工具读取所需部分，或提及一个行范围；行范围最多读取文件中的 64 MiB 来定位这些行，因此 `@big.log:1200-1300` 可用于远大于内联上限的日志。二进制文件、超出文件末尾的行范围以及无法读取的文件，都会作为一条说明附加并说明原因。这些情况都不会使该轮次失败。
- **文件夹**会按广度优先列出：顶层完整列出，然后在列表仍有空间时列出更深层，最多 400 个条目，内容被截断的文件夹会被标记。文件夹在消息发送时读取，因此刚刚写入的文件夹也会被完整列出。在 git 检出目录内，列表会省略 `.gitignore` 所省略的内容；位于任何检出目录之外的文件夹，或整体被 git 忽略的文件夹，会向下遍历四层，跳过隐藏文件夹、版本控制文件夹和依赖缓存（`node_modules`、`.venv`、`__pycache__` 等）。
- **会话**是至多 24 KiB 的摘要：标题、工作区、运行时间、其压缩摘要（如果有，且并非全部能放下时取最新的，并始终包含长轮次摘要所携带的请求）、最新消息（用户的文本和助手的回答；工具结果会被省略，并用一行列出每个回答调用的工具），以及其完整对话记录的路径，供摘要未覆盖的内容使用。它来自另一段对话的上下文，而不是针对当前对话的指令。
- **规则**携带其正文和文件路径。
- **文档页面**是二进制程序所携带的页面，或者在使用 `#section` 时是该节及其子节，最大 64 KiB：每篇指南都能完整放入，而较长的参考页面（HTTP API、Web 界面规范）会以开头部分到达，并附上继续阅读的行号和其各节，供模型用 `coddy_docs_read` 读取所需部分。页面名称采用[内置文档](built-in-docs.md#页面和章节)列出的拼写（`@coddy:mentions` 能找到 `features/mentions`）；末尾的 `.`、`/` 或 `#` 会结束提及，不存在的页面或章节仍作为普通文本。在 Web 界面中，已发送的 `@coddy:` 提及是一个链接，可在文档阅读器中打开该页面，智能体在回答中写出的提及也是如此。
- **子智能体**是一条指示：用 `spawn_agent` 将请求中适合它的部分委托出去。在询问模式下，或对于等待批准的项目定义，附件会说明为什么无法启动它。
- **网页**会在消息发送时通过 webfetch 工具的传输和地址防护机制抓取：仅限公共地址，每个重定向都会经过审查，超时 20 秒，文本上限 64 KiB。无法读取的页面会连同原因一起附加。

## 提及与提示词缓存

提供商按请求前缀进行缓存，而每个请求都以系统消息开头。提及绝不能移动它之前的内容，因此：

- 提及只会在其消息进入对话时解析一次，消息会连同附件一起持久化。后续轮次会逐字节重放它；之后编辑的文件不会重写旧消息，再次提及它才能让模型看到新版本。
- 规则绝不会因为提及而进入系统提示词。用户点名的规则会随用户消息传递，被提及路径激活的规则也是如此，例如模式匹配该文件的 glob 规则、它上方某个子文件夹的规则文件夹中适用于它的规则，以及一直到它为止的各文件夹的 `AGENTS.md` 和 `DESIGN.md`。只要该消息仍在模型的视野中，后续任何工具调用或提及都不会再次附加这些规则；当压缩把该消息并入摘要后，下一次匹配会让它们重新出现（[规则与提示词缓存](rules.md#规则与提示词缓存)）。
- 以 `/name` 调用的技能会将其正文写入调用它的消息一次，而不是被添加到碰巧是最后一条的消息中。

`features/prompt_cache_mentions.feature` 记录了完整过程：一个轮次提及文件、点名规则并调用技能，然后是第二个轮次；两个轮次的每个请求都以相同的系统消息开头，并且第二个轮次会原样重放第一个轮次的消息。

## 谁可以提及什么

| 提及 | 操作员的提示词 | 排队的后续消息 | 子智能体的任务（由父模型编写） | Telegram 聊天 |
| --- | --- | --- | --- | --- |
| 文件、文件夹、行范围、规则、文档页面 | 是 | 是 | 是 | 是 |
| 子智能体、计划、网页 | 是 | 是 | 否 | 是 |
| 其他会话 | 是 | 是 | 否 | 否 |

即时通讯聊天不会访问其他会话：聊天中的人并不是主机上其他每个会话的所有者。已完成后台任务启动的轮次（`notify_on_finish`）不会解析任何内容，它的提示词是 Coddy 自己的报告，而不是任何人输入的文本。

工作区之外的路径会以 `read` 工具所具有的相同访问范围读取：提及是操作员在指向一个文件，它不需要任何模型自身读取本就不需要的权限。

## 补全

候选项来自每个界面共享的同一次搜索（`GET /coddy/mentions`、`session.Manager.SearchMentions`）：会话工作区中的文件和文件夹会根据输入内容排序，先按文件名，再按路径段，再按字母顺序，因此 `@targhand` 能找到 `zz/deep/target_handler.go`；这些结果再与名称匹配的规则、子智能体和计划合并。以 `/`、`~`、`./`、`../` 或盘符开头的查询会改为浏览该文件夹，并按最后一个分隔符之后输入的名称过滤。`@session:`、`@rule:` 和 `@agent:` 会列出该类型，而 `@rule:` 会遍历规则地址树：在规则之前，它会提供所输入文件夹下一层的文件夹、规则文件夹中的文件夹，以及工作区中同样保留 `.coddy/rules/` 的子文件夹，每项都是一步，然后提供地址以该文件夹开头的每条规则，并且只读取它引导进入的规则文件夹（[命名规则](rules.md#命名规则)）；`@coddy:` 会列出文档页面，按名称查找页面，并按章节中的词查找章节（`@coddy:prox`），在 `@coddy:<page>#` 之后则列出该页面的各节。空的 `@` 会先提供那四类，然后提供工作区顶层；方案名称的开头会优先提供该方案（`@ag` 会提供 `@agent:`），因此逐字母输入 `@agent:` 时，即使所在文件夹中没有任何内容匹配 `ag`，也能找到子智能体。在 Web 界面的新聊天中，首条消息之前，工作区是开始屏幕上选定的文件夹：`@agent:` 会提供该文件夹在 `.agents/agents` 或 `.coddy/agents` 中定义的子智能体（项目定义仍要在 `subagents.project_trust` 下等待批准），文件和文件夹以及规则也来自该文件夹。

工作区索引在 git 检出目录内来自 `git ls-files`（因此由 `.gitignore` 决定，像 `.github/workflows/ci.yml` 这样的点文件仍可访问），在其他位置则来自一次遍历，会跳过隐藏文件夹和依赖缓存，上限为 50,000 个条目。每当提及开始时都会重建索引，因此刚刚写入的文件（无论由你还是由智能体写入）会被提供，而已删除的文件则不再出现。

### 在控制台中

输入 `@` 会在编辑器下方打开列表。列表会随着输入而缩小，按 **tab** 或 **enter** 选中高亮行，按 **escape** 关闭。文件夹或方案行会让列表保持打开并显示其内容；文件会用空格结束提及。含空格的路径会以带引号的形式插入；对于文件夹，右引号会插在光标之前，因此即使后面没有文件，文本也能命名该文件夹。当搜索匹配项多于列表可容纳数量时，滚动行会说明这一点：`(3/50 of 1204, type to narrow)`。在没有 `@` 的词上按 **tab** 会将其补全为路径。

![控制台中对 "@ment" 的提及列表：来自整个目录树的一个文件夹和四个文件，每项都标有类型，滚动行显示共有 311 个匹配项](../../assets/cli-tui/18-mention-list.png)

*此仓库中的 `@ment`：名称最先匹配的文件夹，然后是文件，每行都标明类型；滚动行显示列表包含 311 个匹配项中的 50 个*

在远程模式下（`coddy --remote`），列表来自服务器，即会话运行及其提及将被读取的位置，而不是控制台启动时所在的文件夹。

### 在 Web 界面中

输入框的选择器会显示每个候选项及其类型：文件、文件夹、会话、规则、子智能体、计划；空的 `@` 会先显示该会话最近的选项。方向键移动高亮，按 **enter** 或 **tab** 选中，并且在一轮运行期间也可用，因此后续消息也能提及文件。被截断的列表会在标题行说明匹配了多少项。在文件后输入 `:` 会打开[行范围选择器](../surfaces/web-ui.md#行范围pathn-m)。

![Web 输入框中对 "@ment" 的提及选择器：来自整个目录树的文件夹和文件，每项都标有类型，标题行显示 "311 个中的 50 个，输入以缩小范围"](../../assets/mentions/mentions-picker-dark-1280.png)

*`@ment`：工作区按片段排序，每行标明类型，标题行标明截断*

![在 "@session:" 之后的选择器：此工作区的另一个会话，带有标题、id 和最后活动时间](../../assets/mentions/mentions-session-dark-1280.png)

*`@session:` 会列出其他会话，此工作区的会话排在前面，并带有标题、id 和最后运行时间；选中一个会附加其最新消息的摘要*

输入框会按输入原样发送文本：服务器负责解析提及，因此同一份草稿在浏览器中和控制台中含义相同。只有当服务器表示发送会附加该提及后（`POST /coddy/mentions/check`，即同一个解析器在不读取任何内容的情况下运行），输入框才会高亮提及，并且只高亮实际解析的部分：`npm install @google/genai` 中的 `@google/genai` 仍为普通文本，而在 `compare @src/a.go b.go` 中只有 `@src/a.go` 会被标记。

### 在通过 ACP 接入的编辑器中

像 Zed 这样的编辑器有自己的提及菜单，并会将所选内容作为 ACP 内容块发送。带文本的 `resource` 会按发送时的内容附加（Zed 会包含未保存的编辑）；用行片段命名的 `file://` 资源（`#L10-20`、`#L10:20`、`#L10`）会携带这些行，而像 `?symbol=` 这样的查询会被丢弃。指向本地文件或文件夹的 `resource_link` 会像提及它一样被读取；Coddy 无法打开的链接（编辑器内部 URI）会以一行标明它的文本到达模型。作为文本输入的提及会像其他地方一样解析。参见 [ACP 协议](../reference/acp-protocol.md)。

### 在 Telegram 中

输入提及；在读取提示词之前，机器人自己的 `@name` 会被移除。
