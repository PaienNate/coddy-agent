# 桌面窗口

`coddy desktop` 会在你自己的机器上将 Coddy 作为应用程序打开：一个带有标签栏的窗口，每个标签页一个聊天，覆盖在 `coddy serve` 所服务的同一 Web 界面之上。它是普通二进制文件的一个子命令，发布构建中包含它，可在 Linux、macOS 和 Windows 上运行。

![带有两个标签页、前方是一个聊天的桌面窗口](../../assets/desktop/desktop-tabs-dark-1280.png)

*两个聊天作为标签页：前方那个以其会话命名，`+` 会打开另一个。*

## 它是什么

窗口承载你已经熟悉的 Web 界面。每个标签页都是该界面重新加载后的实例，因此在另一个标签页中工作时，某个标签页背后的聊天会保留其对话记录、滚动位置和事件流。智能体、会话和配置都相同：窗口是普通 HTTP 界面的客户端，该界面在此机器的环回端口上启动。

与打开浏览器相比，窗口增加的功能：

- 它作为程序启动，可从启动器或终端启动，无需输入地址；
- 它以标签页并排容纳多个会话，并在重启后回到它们；
- 它是自己的窗口，聊天周围没有地址栏、书签或其他标签页；
- 它让智能体的会话 cookie 不进入你用来读邮件的浏览器。

从启动到框架中的聊天，各部分如何组合：

![桌面窗口如何工作：启动器、窗口中的页面及其框架中的聊天](../../assets/diagrams/desktop-window.png)

*一个进程在记住的环回端口上提供 Web 界面，并据此打开一个浏览器窗口；该窗口中的页面是一个标签栏，覆盖每个聊天一个框架，并通过自己的路由驱动窗口。*

## 获取方式

每个发布二进制都包含该窗口，因此已安装的 Coddy 已经拥有它：

```bash
coddy desktop
```

在源码检出中，`make desktop` 是带有随附标签集的 `make build`：

```bash
make desktop        # build/coddy with tags: http ui scheduler memory cli gateway swarm metrics browser desktop
./build/coddy desktop
```

在已经包含 HTTP 服务器和 Web 界面的二进制中，该界面只占 0.44 MiB，因此它是一个子命令，而不是需要安装和更新的第二个程序，也因此每个构建都包含它：发布归档、软件包、Homebrew formula 和容器镜像都一样。

它需要安装 Chromium 系浏览器，例如 Chrome、Chromium、Edge、Brave、Vivaldi 或 Yandex Browser，它会以应用程序模式启动该浏览器。Firefox 没有应用程序模式，因此不会被使用。

### Linux 软件包

`coddy-desktop` 是与 `coddy` 并列的独立软件包，它不包含程序：它安装菜单项（`/usr/share/applications/coddy-desktop.desktop`）及其指定的图标，因此 Coddy 会出现在应用程序启动器中，并可从那里启动而无需终端；它依赖 `coddy`，其 `desktop` 子命令就是该窗口。只运行 `coddy serve` 的服务器只安装智能体。

```bash
make deb-desktop    # dist/coddy-desktop_<version>_linux_<arch>.deb
make rpm-desktop    # the same as an .rpm
```

与智能体的软件包一样，它不启用任何内容，不创建系统账户，也不在 `/etc` 下写入任何内容；窗口状态属于调用用户的 `~/.coddy`，而 **登录时打开** 会写入该用户自己的自启动文件夹。浏览器是建议而非依赖：Chromium 系中的任何一个都可以，`CODDY_DESKTOP_BROWSER` 可指定另一个。

## 运行它

```
coddy desktop [--window auto|browser|native] [--browser PATH] [--frame] [--auth]
              [--config PATH] [--home DIR] [--cwd DIR] [--log-level LEVEL] [-t]
```

| 标志 | 作用 |
| --- | --- |
| `--window` | 要打开哪种窗口：`auto`（默认）、`browser` 表示应用程序模式、`native` 表示围绕系统 WebView 的窗口，后者尚未内置 |
| `--browser` | 用于打开窗口的浏览器，可在 `PATH` 上按名称指定，或按路径指定。也可用 `CODDY_DESKTOP_BROWSER` |
| `--config`、`--home`、`--cwd` | 与 `coddy serve` 上相同：配置文件、智能体主目录、新聊天打开的工作区 |
| `--frame` | 保留系统标题栏和边框。不指定时，在 X11 会话中，标签栏就是标题栏 |
| `--log-level` | `debug`、`info`、`warn` 或 `error`，覆盖配置 |
| `--auth` | 要求提供配置携带的凭据。不指定时，窗口不要求任何东西（见下文） |
| `-t`、`--test-config` | 检查配置文件并退出，不启动任何内容 |

窗口只运行 Web 界面，不运行其他内容。如果配置还启用了 Telegram 机器人、Pachca 机器人、集群中继、调度器、导出器或浏览器端点，会按原样保留它们；此进程只是不启动它们，启动时会说明这一点，并把它们留给 `coddy serve`。在一个智能体主目录上运行两遍并不会分担工作：同一个令牌上的两个机器人会让 Telegram 对 `409` 作出响应，两个调度器会把每个任务触发两次，而无法绑定端口的中继会连带拖垮窗口。

## 标签页

| 操作 | 方法 |
| --- | --- |
| 新建标签页 | 标签页后的 `+`，或 `Ctrl`+`T` |
| 关闭标签页 | 其 `×`、在它上面中键单击，或对最前面的标签页按 `Ctrl`+`W` |
| 切换 | 单击标签页，或 `Ctrl`+`1` …… `Ctrl`+`9` |
| 下一个、上一个 | `Ctrl`+`Tab` 和 `Ctrl`+`Shift`+`Tab`，两端循环 |
| 重新加载最前面的聊天 | `Ctrl`+`R`，只会重新加载该标签页，不影响其他标签页 |
| 浏览很长的一行 | 窗口自身按钮旁的两个箭头，当标签页总宽度超过栏宽时出现 |

这些组合键在你于聊天中输入时也有效，其中一些需要绕道才能到达。应用程序模式下的浏览器窗口会自己响应 `Ctrl`+`T`、`Ctrl`+`W`、`Ctrl`+`R` 和 `Ctrl`+`Tab`，分别会新建浏览器窗口、关闭应用程序、重新加载整个标签栏以及切换它自己的标签页，任何页面都无法取消其中任何一个。在 X11 会话中，启动器在 X 服务器处捕获这些键，通过在其自己的窗口上抓取，并把它们交给标签栏；`Ctrl`+`Tab` 和 `Ctrl`+`Shift`+`Tab` 是两次抓取而不是一次，因为抓取会精确匹配修饰键。`Ctrl`+`1` …… `Ctrl`+`9` 不需要这些，因为应用程序窗口没有自己的标签页可切换，会把数字键交给页面。对每个组合键，`Alt` 都与 `Ctrl` 并列存在，在 Mac 上 `Cmd` 也是如此：这就是 Wayland 或 macOS 会话留给你的方式，在这些会话中无法从浏览器那里取得这些键。组合键按物理按键读取，因此俄语或任何其他布局都会响应与美式布局相同的按键。

比栏更长的一行会滚动，切换到的标签页总会被带入视野，因此无论打开多少聊天，组合键都保持可用。

标签页以其背后的会话命名，窗口从会话列表读取名称。尚未开始的聊天为 `New chat`。

在名称之前，每个标签页带有其聊天状态，与历史记录列表使用的标记相同：

| 标记 | 含义 |
| --- | --- |
| 一个脉动的实心点 | 聊天正在工作：一个轮次正在运行，或后台任务仍在进行中 |
| 主题强调色的圆环 | 聊天正在等你，等待权限或回答 |
| 红点 | 该聊天的最后一个轮次失败 |
| 强调色的实心点 | 聊天在你位于另一个标签页时完成 |
| 空心圆环 | 聊天已完成 |

窗口始终保留一个标签页：关闭最后一个会打开一个空聊天，而不是让窗口空白。当启用 **显示托盘图标** 且图标存在时，标签栏的关闭按钮会最小化窗口：应用程序及其背后的界面继续运行，单击图标或选择 **显示窗口** 会让窗口回来。关闭托盘，或图标无法显示时，同一个按钮会关闭应用程序并停止界面。无论该开关处于什么状态，托盘菜单中的 **退出 Coddy** 总会结束应用程序。从托盘自己的菜单关闭 **显示托盘图标** 时，会先恢复最小化的窗口，再移除图标，因此恢复路径不会随之丢失。

每个标签页都是 Web 界面的完整实例，因此内存会随标签页数量增长，程度大致相当于同样数量的浏览器标签页。事件流不会成倍增加：同一来源的每个实例共享一条连接。

## 窗口本身

在 X11 会话中，窗口打开时没有系统边框，标签栏就是其标题栏。在 macOS、Windows 和 Wayland 上，窗口保留桌面绘制的边框，标签栏就是一条标签页栏：下文所述都是 X11 会话额外提供的内容。标签栏从左到右包含：桌面菜单、标签页、`+`、可拖动窗口的空白区域、用于浏览超出栏宽的一行的两个箭头，以及右边缘的最小化、最大化和关闭。窗口浮动时圆角，铺满屏幕时直角。

| 操作 | 方法 |
| --- | --- |
| 移动窗口 | 拖动标签栏的空白部分 |
| 最大化或还原 | 双击标签栏的空白部分，或点击右侧的中间按钮 |
| 最小化、关闭 | 右边缘的按钮 |
| 桌面菜单 | 标签栏左边缘的按钮 |

窗口管理器已固定的窗口，例如已最大化，或通过 `Meta`+`Left` 贴靠到边缘平铺，会在你开始拖动标签栏时被释放，并重新置于指针下方，就像在任何地方拖动标题栏那样。你的桌面的键盘指令会像应用于任何其他窗口一样应用于此窗口。

浏览器配置文件的第一个窗口会以横向矩形打开，尺寸为 1280 × 820，而不是 Chromium 应用程序窗口默认采用的竖向尺寸。此后浏览器会记住你把它留在哪里，Coddy 不会覆盖这一点：移动或调整大小后的窗口会回到原来的位置。

### 在任务栏中

窗口属于 Coddy，并且以两种方式告知桌面这一点。它带有窗口类 `coddy-desktop`，任务栏用它已知的应用程序项进行匹配，因此已安装的 Coddy 会在此显示自己的图标和自己的菜单，而不是浏览器的；没有它时，窗口类会从窗口打开的地址推导出来，任务栏会找到浏览器的项，右键单击会提供浏览器的最近下载和新建无痕窗口。并且它在未安装菜单项的机器上把 Coddy 的标记作为自己的图标，尺寸为 48 和 128 像素：浏览器给应用程序窗口的是页面 favicon 的 16 像素版本，没有更大的，任务栏随后会把它模糊放大到自己的尺寸。

两者都是 X11 的。在 Wayland、macOS 和 Windows 上，就系统而言窗口属于浏览器，任务栏绘制浏览器告知它的内容。

### 应用程序菜单中的最近文件夹

在 Linux 上，每次启动都会写入此用户自己的应用程序项 `~/.local/share/applications/coddy-desktop.desktop`，并指明写入它的二进制文件。这让 Coddy 在未安装软件包的情况下出现在启动器和任务栏菜单中，并且它把此主目录最近聊天的文件夹作为其操作，最多六个，最新的在前。右键单击图标会提供它们，选择其中一个会在该文件夹中打开新聊天：该行运行 `coddy desktop --new-chat --cwd <folder>`，它会把文件夹交给已经打开的窗口，而不是启动第二个窗口。

一行会命名该文件夹及其上一级（`coddy-agent/docs`），因为这样才能区分同一仓库的两个检出；完整路径在命令中。某一行打开的文件夹也会成为下一次新建聊天启动时所在的文件夹，和在开始屏幕上选择它一样。

标签栏采用聊天所在的主题。它从最前面的聊天读取颜色，因此 Web 界面的全部九个主题都能应用到栏、标签页和状态点，在 **设置** 中更改主题后无需重新加载即可应用到标签栏。

## 桌面菜单

标签栏左边缘的按钮会打开窗口自己的设置。这些设置属于这台机器，而不是页面，存放在 `<home>/desktop/settings.json` 中，因此即使某次启动不得不使用另一个端口，它们也会保留。

![在标签栏左边缘按钮下打开的桌面菜单](../../assets/desktop/desktop-menu-dark-1280.png)

*从标签栏左边缘打开的窗口菜单。*

| 条目 | 作用 |
| --- | --- |
| **新建聊天** | 与 `+` 相同 |
| **登录时打开** | Linux：将 `coddy-desktop.desktop` 写入此用户的自启动文件夹（`$XDG_CONFIG_HOME/autostart`，否则 `~/.config/autostart`）。macOS：启动代理，`~/Library/LaunchAgents/dev.coddy.desktop.plist`。Windows：此用户 `Run` 键下的一个值。不会在系统范围安装任何内容，也不需要管理员权限 |
| **显示托盘图标** | 在会话总线上将 Coddy 的标记作为 StatusNotifierItem 发布到系统托盘。单击它会将窗口从其他窗口后面或任务栏中带回 |
| **启动时最小化** | 下次启动会以最小化方式打开窗口，这通常正是登录时打开的窗口所需要的 |
| **显示系统边框** | 让窗口恢复桌面绘制的标题栏和边框。标签栏随后不再绘制最小化、最大化和关闭，因为边框已包含它们。仅限 X11 会话：其他环境中边框始终存在 |

只有启动器完成相应操作后，开关才会改变：如果此会话没有可供使用的托盘，或自启动文件夹无法写入，开关会保持原状，并在该行说明原因。

托盘图标带有相同的菜单。右键单击它会打开上面的各行，并在顶部多出两项，**显示窗口**，将其从其他窗口后面或任务栏中带回，以及 **隐藏窗口**，再次将其收起；底部还有 **退出 Coddy**，位于单独一条分隔线之后：当窗口隐藏在托盘中时，图标是退出应用程序的唯一途径。标签栏中的菜单没有这一行，因为窗口自己的关闭按钮就在它旁边。这两个菜单由 Go 侧的一个列表绘制（`shell.MenuRows`），因此添加到标签栏菜单的行也会出现在图标菜单中；该图标使用 `com.canonical.dbusmenu`，这是 StatusNotifierItem 指定的菜单协议，也是当前每个托盘都会绘制的协议。从图标选择 **新建聊天** 会先带回窗口，因为在隐藏窗口后面打开的聊天没有人要求。

在完全无法驱动窗口的环境中，例如 Wayland 会话，程序不能移动或去除不属于自己的窗口的装饰，窗口会保留系统边框，标签栏也不绘制自己的按钮。其他一切相同。

## 从 Coddy 外链

指向另一个站点的链接，例如文档、议题或模型写下的任何内容，会通过桌面自己的打开器在你实际使用的浏览器中打开。如果在标签页内单击，它原本会把该站点加载到框架中，在那里它会位于标签栏之下，没有地址栏、没有后退按钮，除了关闭标签页之外没有出路。Coddy 自己的地址不是外链，会留在窗口内。

只会移交 `http` 和 `https`。窗口拒绝其他所有方案，因为打开器会把收到的内容交给任何声明处理它的应用程序，而聊天中的链接是模型写下的文本。

## 通知

窗口会发出 Web 界面发出的系统通知。在 **设置 - 外观 - 通知** 中开启它们，当没有 Coddy 窗口获得你的注意时，结束一个轮次、请求权限或提出问题的聊天会在你的桌面上放置一条通知；单击它会使该聊天出现。规则属于 Web 界面自身，见 [通知](web-ui.md#通知)。

窗口增加的一点是它不会询问。全新的浏览器配置文件会在其第一个窗口之前就被告知答案，因此打开开关不会在标签栏上方弹出浏览器的权限气泡。授权只指明此窗口的地址，不包含其他内容，并且由于端口保持不变而持续有效。如果某次启动不得不使用另一个端口，获得的授权就不再匹配，浏览器会询问一次。

## 它记住的端口

首次启动会取一个空闲环回端口并写入 `<home>/desktop/port`；之后每次启动都在同一个端口上提供服务。浏览器以端口为范围存储页面状态，因此保留端口才能让窗口回到你离开时打开的标签页，并让首次运行导览保持已看过的状态。

两个后果：

- 如果其他程序占用了该端口，本次启动会改用另一个端口并说明这一点。该次启动不带任何标签页，而下一次启动会使用新端口；
- 在窗口已经打开时启动应用程序不会再次提供服务。第二次启动会看到桌面已在运行，并向它请求一个窗口。

窗口使用的浏览器配置文件位于 `<home>/desktop/profiles/<browser>`，每个浏览器一个。它使窗口成为独立进程，并使智能体的 cookie 不进入你的日常配置文件。它占用的磁盘空间与全新浏览器配置文件相同，为几十兆字节。

## 登录

窗口不要求任何东西。它为启动应用程序的人绑定环回地址，而用户自己打开的窗口中的登录表单证明不了什么，因此无论配置携带什么凭据（bearer 令牌、登录账户或两者），`coddy desktop` 都不需要凭据即可提供服务。

**磁盘上的配置不受影响。** 同一个 `config.yaml` 仍可登录从其他地方可访问的 `coddy serve`，窗口内的设置屏幕显示真实值，因此从那里保存不会把操作员的账户从磁盘上移除。

由此产生两点。这台机器上运行的任何程序都能访问该端口并驱动智能体，这与 `coddy serve` 在环回上默认达成的交易相同。如果你想要回凭据，例如共享机器、第二个用户账户，`--auth` 会要求配置所配置的任何凭据，登录表单会出现在窗口内。

如上所述，窗口只运行 Web 界面，不运行其他内容，这也是此进程的决定，而不是对配置的编辑：其他子系统根本不在它启动的界面之列。

## Linux、macOS 和 Windows

窗口在三个系统上都能打开。不同之处在于系统允许 Coddy 驱动其中多少内容：

| | Linux (X11) | Linux (Wayland) | macOS | Windows |
| --- | --- | --- | --- | --- |
| 窗口、标签页、设置 | 是 | 是 | 是 | 是 |
| 无系统边框，标签栏作为标题栏 | 是 | 否 | 否 | 否 |
| 圆角、通过标签栏拖动、自己的按钮 | 是 | 否 | 否 | 否 |
| 从浏览器取得的 `Ctrl`+`T`、`Ctrl`+`W`、`Ctrl`+`R`、`Ctrl`+`Tab` | 是 | 否 | 否 | 否 |
| 相同组合键使用 `Alt`（在 Mac 上还有 `Cmd`） | 是 | 是 | 是 | 是 |
| 托盘图标 | 是 | 是 | 否 | 否 |
| 登录时打开 | 自启动项 | 自启动项 | 启动代理 | `Run` 键 |

在无法从浏览器取得组合键的地方，`Alt`+`T`、`Alt`+`W`、`Alt`+`R` 和 `Alt`+`Tab` 会做同样的事，在 Mac 上 `Cmd` 与它们并列。

浏览器会到各系统存放它的位置查找：Linux 上在 `PATH` 中，macOS 上在 `/Applications` 和 `~/Applications` 中，Windows 上在 Program Files 和用户的本地应用程序数据下。对于把浏览器放在别处的机器，`CODDY_DESKTOP_BROWSER` 可按路径指定一个：

```bash
CODDY_DESKTOP_BROWSER="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" coddy desktop
```

在 macOS 或 Windows 上使用它之前需要知道两件事。Gatekeeper 和 SmartScreen 在这里都没有什么可警告的，因为你启动的程序是机器上已安装的浏览器，但 `coddy` 本身是控制台程序，所以在 Windows 上，启动它的控制台窗口会留在窗口后面。而且由于没有自己的窗口可驱动，标签栏不绘制窗口按钮，菜单也不提供边框开关：桌面自己的标题栏同时承担这两者。

如果根本没有找到 Chromium 系浏览器，启动会打印地址并持续提供服务，直到你停止它，因此仍然可以在普通浏览器中访问该界面。
