# Pachca 网关

Coddy 可以在企业即时通讯工具 [Pachca](https://pachca.com/)（Пачка）中作为你工作区的集成机器人作答。人员可以在私聊中给机器人写消息，在群聊中提及它，或在线程中回复它，消息会启动或继续一个智能体轮次；回答会以流式传输写入聊天中的一条消息。机器人运行在 `coddy serve` 内，与 HTTP 服务器和 Telegram 机器人并列，并且每个对话都是普通的 Coddy 会话，因此 Web 界面会实时显示它。

该适配器有意比 [Telegram 网关](gateway.md) 更小：它读取机器人的事件历史，而不是接收 Webhook，因此运行 Coddy 的机器不需要公共地址；它涵盖聊天轮次、少量命令、用于模型菜单和子智能体权限提示的按钮，以及被唤醒的轮次。

## 在 Pachca 中设置机器人

1. 在 Pachca 的 Web 或桌面应用中打开 **自动化 → 集成 → 聊天机器人和 Webhook**（Automations → Integrations → Chat bots and webhooks；Автоматизации → Интеграции → Чат-боты и Вебхуки），按 **+** 并选择 **用于多个聊天**，这样机器人就能与每个人和群组交谈（"用于一个聊天"的机器人仅限于一个对话或频道，线程和私聊除外）。在 **API** 选项卡上复制其 `access_token`。这是普通的集成机器人，不是个人令牌：机器人以自身身份行动，角色为员工，其消息带有机器人徽章。
2. 在机器人的 **API** 选项卡上授予适配器使用的权限范围：
   - `messages:create`、`messages:update`、`messages:read` - 发布、流式编辑、识别对机器人的回复；
   - `chats:read` - 区分私聊与群组；
   - `profile:read` - 机器人自己的昵称，提及时会用到它；
   - `users:read`（推荐） - 引用回复中的作者名；
   - `webhooks:events:read` - 读取事件历史；
   - `webhooks:events:delete`（推荐） - 移除已处理事件，使历史不会增长。
3. 在 **Outgoing webhook** 选项卡上：
   - 开启 **保存事件历史**（`events_history_enabled`）。不开启的话历史始终为空，机器人什么也听不到；Webhook URL 本身可以留空；
   - 订阅 **新消息** 的 "任意消息" 模式和 **按钮点击**；
   - 开启 **忽略自己的消息**。适配器无论如何都会过滤机器人自己的消息，但没有理由读取它们。
4. 将机器人添加到它应工作的聊天中。机器人会自行看到公开频道；私密对话或频道需要机器人作为成员，线程也可以直接拉入机器人。当机器人是公开的、先给对方写过消息，或对方与它共享聊天时，人们可以在私聊中给机器人写消息。

## 配置

```yaml
gateways:
  pachca:
    enable: true
    token: ""                    # or PACHCA_BOT_TOKEN in the environment or ~/.coddy/.env
    proxy: ""                    # inherit (default), none, or an http(s)/socks5(h) proxy URL
    poll_interval_seconds: 2     # 1 to 60
    admins: [12345]              # Pachca user ids
    default_access: all          # all | admins | group:<name>
    default_isolation: individual  # individual | shared | admin
    user_groups:
      - name: devs
        user_ids: [12345, 67890]
    chats:
      - chat_id: 334
        isolation: shared
        access: group:devs
```

访问与隔离的读取方式与 Telegram 完全相同（[访问级别](gateway.md#访问级别)、[会话隔离模式](gateway.md#会话隔离模式)）：`default_access` 决定谁可以与机器人交谈，`default_isolation` 决定群聊是每人一个会话、所有人一个会话，还是仅管理员一个会话，`chats[]` 按聊天覆盖这两者。私聊始终拥有自己的会话。线程在 Pachca 中有自己的聊天 id，因此每个线程也是自己的对话。

将 `token` 留空并导出 `PACHCA_BOT_TOKEN`（例如在 `~/.coddy/.env` 中），以免机密进入 `config.yaml`。相同的键位于 Web 设置的 **网关** 选项卡上，在那里更改令牌或任何其他键会在原地重建 Pachca 机器人，同时让同一进程中的 Telegram 机器人继续运行。字段参考见 [config.md](../reference/config.md)。

## 运行

该适配器位于 `gateway` 构建标签之后（或仅用于此适配器的 `gateway.pachca`）；发布二进制文件、软件包和 Docker 镜像都包含它。

```bash
make build TAGS="gateway.pachca"
```

```bash
coddy serve --dry-run
```

`--dry-run` 使用 `GET /oauth/token/info` 检查令牌：令牌缺失或被撤销、缺少必需权限范围时给出错误；仅缺少推荐的 `webhooks:events:delete` 或 `users:read` 时给出警告。然后启动服务器：

```bash
coddy serve
```

横幅会显示机器人名称（`gateway     pachca`），日志会以其昵称说明 `pachca bot connected`。`CODDY_PACHCA_API_BASE` 将机器人和试运行指向另一个 API 基础地址，例如测试服务器；默认值为 `https://api.pachca.com/api/shared/v1`。

## 机器人的行为

- **私聊**：每条消息都是给机器人的，无论是否提及或回复。
- **群聊或频道**：群组是多人交谈的地方，因此机器人只回答提及它（`@nickname` 或 `<@id>`）的消息，或回复其某条消息的消息。命令也需要提及，在机器人消息下打开的线程中的消息也是如此。其他所有内容都留给聊天中的人。
- **回复**：回复某条消息的人是在询问该消息。智能体会在对方所写内容之前收到被回复消息的引用，第一行注明其作者（`> Anna:`），无论私聊还是群组、无论是对机器人自己的回答还是同事的消息。仅有一条提及且位于回复之下时，会要求智能体处理被引用的消息。引用会保留在会话的对话记录中；设置命令永远不会被引用。注明作者需要 `users:read` 权限范围；没有它，引用就没有作者行。
- **顺序与追赶**：机器人每隔 `poll_interval_seconds` 读取事件历史，从最新到最旧，直到它处理的最后一个事件，然后将新事件从最旧到最新交出。位置保存在 `<sessions>/gateway_pachca_state.json` 中，因此重启后会回答机器人停机期间写入的内容。第一次启动从历史中最新的那个事件之后开始，不处理更早的事件。
- **每个会话一次只处理一个轮次**：同一对话的消息会在正在运行的轮次后面排队，停止或重启会最多等待 20 秒，让正在运行的轮次和已排队的轮次完成，然后机器人退出。发现队列已满（32 个等待）的消息不会被接收，并会通知聊天重新发送。
- **短暂失败不会丢失任何内容**：当 Pachca 不回答机器人所需的查询（某个聊天是否为群组、回复所回答消息的作者是谁）时，事件会留在历史中，并在下一次轮询时再次读取。
- 聊天到会话的映射保存在 `<sessions>/gateway_pachca_sessions.json` 中，与 Telegram 的分开。

## 命令

| 命令 | 作用 |
|---------|--------------|
| `/help`、`/start` | 命令列表和问候语。 |
| `/clear` | 为对话启动新会话；旧会话保留在磁盘上。 |
| `/model` | 将配置的模型作为按钮发布；点击会切换对话的模型，并且当管理员选择时，机器人的下一个新对话会从该模型开始（其他人的选择保留在自己的会话中）。`/model <id>` 直接设置它。 |
| `/context` | 对话会话的上下文窗口使用情况。 |
| `/goal <objective>`、`/goal`、`/goal pause`、`/goal resume`、`/goal clear` | 会话目标：设置并开始处理、显示、暂停、恢复或移除它（[会话目标与监督器](../features/session-supervisor.md)）。只有机器人的管理员可以更改它；监督器启动的每个轮次都会以自己的消息宣布。 |
| `/agent`、`/plan`、`/ask`、`/think`、`/nothink`、`/reasoning <level>` | 设置命令，像在每个界面上一样交给会话；`--once` 和 `--count=N` 将它们限制为接下来的消息。 |

在群聊中，命令需要提及机器人（`@nickname /clear`）或回复其消息，而更改设置的内容，包括设置命令、`/model` 及其按钮、`/clear`，属于管理员（`admins`）：其他人会收到 *只有机器人的管理员可以在此聊天中更改设置。* 在私聊中，每个人更改自己的会话。`/permissions` 不会从聊天中获取：机器人会自己批准其自身智能体的请求。

## 非管理员可以做什么

机器人能看到每条消息是谁写的。其管理员（`admins`）可以做任何事；其他人只能获得对话，而不能获得任何会改变智能体的操作：只能在会话的工作目录内读取、查看文档、进行 Web 搜索、使用计划和反问；其他所有内容，包括 MCP 工具，都会被拒绝，`@` 提及会留在工作目录内，每个需要批准的调用都会被询问并拒绝，无论会话的权限模式和授权如何，规则与 Telegram 机器人相同。当 `admins` 列表为空时，所有人只能聊天，并且 `--dry-run` 会发出警告（[非管理员可以做什么](gateway.md#非管理员可以做什么)）。被唤醒的轮次和后台子智能体的请求会取得对话所有者的权限。Pachca 没有 Web 界面入口：聊天就是整个界面。

## 回答、限制与格式

回答会在出现最初几个词时作为一条消息发布，并在写入期间最多每两秒就地编辑一次，下方带有正在运行的工具名称；结束时，该消息会被完整回答替换。编辑不计入 Pachca 的每聊天消息数限制。长于一条消息的回答会在后续消息中继续，而 Pachca 因过长而拒绝的片段会再次拆分。

Pachca 会渲染粗体、斜体、删除线、链接、行内代码和围栏代码块，并将 `#` 标题显示为粗体行。它不会渲染列表或表格。机器人会在每个轮次告诉模型这一点，并在输出时将 Markdown 表格转换为围栏文本块，并在引用前放置一个竖线，否则 Pachca 会丢弃引用的 `>`。

短暂的速率限制（`429`，暂停最多一分钟）会被等待过去。每个聊天的每日消息限制永远不会重试，因为该暂停期间的每次尝试都会使其翻倍；此时回答不会送达，日志会说明这一点。

## 权限与被唤醒的轮次

管理员的自身智能体可以执行它所请求的操作，就像在 Telegram 中一样：操作员是有意配置该机器人的；对于其他任何人，什么都不会被批准（见上文）。对于定义缩小了可执行范围的子智能体、`PreToolUse` 钩子的 `ask`，以及未通过 [决策检查](../features/decisions.md) 的命令，机器人会在聊天中通过 **允许** 和 **拒绝** 按钮询问，并且只有在该聊天中其会话正是发起询问会话的机器人管理员才能回答：在隔离模式为 `shared` 的群组中，会话是所有人的，因此非管理员成员无法回答。后台子智能体在轮次结束后也会以同样方式询问。智能体使用 `notify_on_finish` 启动的后台任务会在结束时唤醒对话，被唤醒的轮次会在其所属聊天中运行：先有一条说明指出是什么唤醒了智能体，然后给出回答。

## 不支持的功能

Webhook 接收（机器人只读取事件历史）、`/resume` 和 `/mcp`、任一方向的图片和文件、表情回应和表单。有人编辑或删除消息不会启动轮次。只有文件没有文本的消息会收到一条说明，指出机器人只读取文本；随文本发送的文件只会以文本形式进入会话。

## 故障排查

- **机器人从不回答，日志也很安静。** 检查 **保存事件历史** 是否开启：不开启的话历史始终为空。启动后历史连续五分钟为空时，机器人会在日志中警告一次。
- **机器人在私聊中回答，但在群组中不回答。** 提及它或回复其消息；在群组中，即使是命令或位于其回答下线程中的消息，也需要两者之一。检查机器人是否是聊天成员，以及 `default_access` 或该聊天的覆盖设置是否允许此人进入。
- **`--dry-run` 报告缺少权限范围。** 在 Pachca 中机器人的 API 选项卡上授予这些权限，并再次复制令牌。
- **历史不断增长。** 令牌缺少 `webhooks:events:delete`；机器人仍会根据其保存的位置工作。
- **仅针对此机器人的调试输出**：`logger.levels` 搭配 `component: gateway.pachca` 和 `level: debug`，或 `--log-level "info,gateway.pachca=debug"`。每个被忽略的事件都会以调试级别记录并附上原因。
